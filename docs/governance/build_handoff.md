依据是已经进入 `main` 的角色手册、多端架构方向、交付决定和协作规则。本文不改产品、体验、界面、学习和架构契约。

# 2. 谁负责什么

| 谁 | 负责 | 不负责 |
| --- | --- | --- |
| Owner | 最终决定和验收 | 不替实施角色改契约来迁就代码 |
| ChatGPT | 总控、Gate Review、重大需求变化、跨角色冲突、最终放行 | 不直接改仓库里的业务代码 |
| Cursor | THINK 阶段的专业角色工作台。BUILD 阶段做契约监工和专业 Review。发现 `CONTRACT_CONFLICT` 时阻断 | 不自行改已冻结的上游契约，不把冲突悄悄修成新设计 |
| Grok Bot | Core Learning Engine、业务逻辑、通用前端、测试、重构 | 不把学习逻辑写进某一个平台的页面里 |
| WorkBuddy | 微信小程序的平台接入、构建、开发者工具、发布、环境与部署 | 不单独拥有核心学习引擎，不决定产品或学习规则 |

Cursor 在 THINK 里可以调用 Product、UX、Learning、UI、Brand、Architecture 等角色来提议和写文档。这些角色建议，Owner 决定。

# 3. 架构硬边界

```text
Core Learning Engine
核心学习引擎
        ↓
不得直接调用微信、抖音、支付宝或浏览器专有 API
        ↓
Platform Adapter
平台适配层
        ↓
微信小程序 / H5·PC / 以后的抖音、支付宝
```

产品契约和学习契约属于核心层。平台 API 属于适配层。

Core Learning Engine 包含题目、判题、掌握、反馈、记忆钩子和本地学习状态。这些规则在各端必须得到同一种结果。

存储、音频、动画能力、导航、分享、打印、分享或保存，以及平台生命周期，走 Adapter。登录只有以后被单独批准才接入。

Grok Bot 写核心和通用前端。WorkBuddy 接微信这一端的壳、构建和发布。两边都不得把微信 API 写进核心。

# 4. 后端

v0.1 不建后端。不建后端是架构决定，不是少写的代码。

本地题库、判题、进度、掌握、错题、记忆钩子、视觉反馈、音效和静态内容，都不构成建后端的理由。

只有出现明确的服务器职责时，才退出 BUILD，回到 THINK，单独决定。例如：

- 账号
- 跨设备同步
- 多用户
- 师生协作
- 云端内容管理
- 集中分析
- 远程布置作业
- 云端分析或 AI Tutor

在那次决定通过之前，实现仍是仅客户端的。

---

# 5. 什么留在 BUILD，什么退回 THINK

留在 BUILD 的，是不改变冻结含义的实现问题。例如：某个平台 API 的调用方式、构建失败、测试补漏、在已冻结布局里的像素修正。

必须退回 THINK 的，是这些变化：

- 产品范围、目标用户、要不要做某项能力
- 学习逻辑、掌握含义、记忆钩子怎么教
- 体验路径、暂停、结束、答错之后发生什么
- 视觉方向
- 核心与适配层的边界
- 要不要后端、账号或同步
- 把某一个平台的限制写成所有端的产品规则

退回之后：先补对的专业角色，更新对应契约，再经 ChatGPT Gate Review 和 Owner 决定。不要在 BUILD 里直接改契约，也不要让同一个角色把不属于它的层一起改完。

发现实现和冻结契约冲突时，报告 `CONTRACT_CONFLICT` 并停住。不要为了让代码通过而改写产品、体验、界面或学习契约。

# 6. 正式开发的顺序

CF0 通过之后，按这个顺序做。顺序本身不是今天的开工令。

```text
1. 综合记忆反馈原型
   把 A+ 视觉和学习反馈合到同一次可体验页面
   Owner 和孩子看过
        ↓
2. UI / Learning 最后冻结
   然后才是 CF0
        ↓
3. Core Learning Engine
   题目、判题、掌握、反馈、记忆钩子、本地状态
        ↓
4. WeChat Adapter
   微信小程序首发
        ↓
5. H5 / PC Adapter
        ↓
6. 抖音、支付宝
   以后再适配，不在 v0.1 同时发布
```

第 1 步完成之前，不开始大规模正式小程序代码。

框架仍未选定。本文不选定框架，也不选定数据库。
