# 1. Why current feedback is insufficient

PT0 的 Owner 反馈指出两件不同的事。

视觉上，A+ 澄蓝数学实验室可以继续。整体动效还少。若要加空间、悬停、声音，它们必须是 Memory Cue（记忆线索），绑在一条数学关系上，不是装饰。

教学上，当前答错示例是：

```text
15 × 15 = 225
平方就是这个数乘自己。
```

这在数学上没错，对初中生几乎没有新信息。会做 `15²` 的学生通常已经知道平方是自己乘自己。卡住的更常是：想不起来、看不见规律、没有合理性检查、事实彼此孤立。

因此记为：

`LEARNING_DESIGN_CHANGE_REQUIRED`

下一句要回答的是：「我下次怎么把 225 想起来？」

Owner 看过 `learning-exploration/` 后确认：这种解释是目前想要的状态。它方便学生记住关系，而不是把运算再肤浅地说一遍。

`OWNER_LEARNING_FEEDBACK`

这还不是在三个分镜里选定最终版，也还不是 Contract Freeze。它确认的是反馈方向：给一个能提取的记忆点。

# 2. Error taxonomy

没有真实学生记录之前，下面是设计用的错误类型，不是测量结果。

| 类型 | 意思 | 反馈该做什么 |
| --- | --- | --- |
| 概念没懂 | 不知道这个符号在问什么 | 先补最短的意义。数感训练场里这应是少数 |
| 提取失败 | 知道是什么，但数值关系出不来 | 给一个记忆钩子 |
| 看不见规律 | 每题都当新题 | 指出这一家关系 |
| 计算滑了一下 | 方法对，某一步错了 | 点出那一步，不重讲定义 |
| 表示法混淆 | 例如把分数写成看起来像的小数 | 对上正确表示，并给一个范围检查 |

一条反馈只处理最可能的一种。不在同一屏把五种都讲完。

# 3. Feedback depth rules

深度按「下次还能不能想起来」决定，不按「讲得完不完整」决定。

- 通常一屏。
- 一个强钩子，胜过五条弱事实。
- 正确关系始终在。
- 规律、合理性检查、邻近例子按知识类型选用，不必五段齐全。
- 定义学生已经会的，不重复。
- 证明可以存在于设计笔记里，不默认搬上屏幕。

屏幕上的候选层次是：

```text
Correct Relation    正确关系
Memory Hook         怎么记
Reasonableness Check 怎么一眼看它合不合理
Related Examples    这一家
```

# 4. Memory Hook

记忆钩子是一条短的、可重复提取的结构。它不是奖励，也不是笑话。

可靠的钩子来自恒等式或稳定表示。例如个位是 5 的两位数平方：

```text
(10a + 5)² = a × (a + 1) 后面接 25
```

这是代数恒等式，不是顺口溜。

```text
15²    1 × 2 = 2     → 225
25²    2 × 3 = 6     → 625
35²    3 × 4 = 12    → 1225
```

前面的乘积若有两位，就直接接上，例如 12 接 25 得到 1225。不要补成 0225。

口诀若不能还原成这种恒等式或稳定表示，就不用。

# 5. Pattern

规律要标明它是什么：

- 规则：这个表示法的定义。例如 3/4 就是 3 ÷ 4。
- 规律：一组对象共有的结构。例如个位是 5 的整数平方，末位一定是 25。
- 启发式：常常有用，但不是证明。例如「先找一个靠近的整十」。
- 口诀：只有能还原成规律或规则时才保留。
- 证明：设计笔记里可以有，屏幕上默认不放。

「末位是 25」只是规律的一半。能用来记住的是「前面先算 a×(a+1)，再接 25」。

# 6. Reasonableness Check

合理性检查用来一眼排除不可能的答案。它不代替计算。

`15²` 在 `10² = 100` 和 `20² = 400` 之间。个位是 5 的整数平方以 25 结尾，所以 215 立刻不合理。

检查本身也要短。一次只留一条。

# 7. Relation Network

一个错的事实应能看见邻居，而不是变成孤立 trivia。

```text
15² = 225
25² = 625
35² = 1225
```

分数也一样：1/4、2/4、3/4 是一家；1/2、1/4、1/8 是不断取半的一家。

网络只展示两三个邻居。不上知识图谱，不建后端。

# 8. Cognitive Load rules

- 做题时几乎静止。学生在提取，不在看动画。
- 反馈只讲一个教学点。
- 视觉和文字说同一件事。图若不能减少字，就不要图。
- 声音可选，且不能承载唯一信息。关掉声音，关系仍然完整。
- 不循环播放，不在计算时悬浮无关物体。

# 9. Visual Memory Cue

记忆线索是一段短的、按时间排开的视觉，绑在关系上。

`15²` 的概念顺序：

```text
1 × 2
  → 2
  → 接上 25
  → 225
```

首页可以有空间感和轻微悬停。反馈可以用这一小段。做题页不播。

这仍是设计概念。本轮不实现动画。静态分镜见 `learning-exploration/`。

# 10. Optional Audio Cue

声音若以后要做，只作为可选节奏，例如两下轻点再一声完成。它帮助顺序，不帮助「好听」。

本轮没有音频文件，也没有自动播放。关掉声音必须仍然能学。

# 11. Five sample feedback designs

五个例子故意用不同结构。不要把「末位是 5」套到乘法或分数上。

教学效果是否比现在的短句更好，尚未在学生身上验证。数学恒等式本身是确定的。效果标为待复核。

## 11.1 15²

可能的错误类型：提取失败，或看不见「末位是 5」这一家。假设，待复核。不太像「不知道平方是什么」。

正确关系：`15² = 225`

记忆钩子：15 末位是 5，前面的数字是 1。1 × 2 = 2，后面接 25，所以是 225。

规律：`(10a + 5)²` 等于 `a × (a + 1)` 后面接 25。这是恒等式。

合理性检查：在 100 和 400 之间，而且以 25 结尾。215 不合格。

邻近例子：`25² = 625`，`35² = 1225`。

不要讲：平方的定义、完全平方公式的展开证明、超过三个邻居。

视觉线索：`1 × 2` → `2` → `2|25` → `225`。

可选声音：两下轻点，再一声落在 225。关掉也能看完。

把握：恒等式确定。这个钩子是否适合 12～15 岁，待 Owner / 教师 / 学生复核。

## 11.2 25²

可能的错误类型：同一家关系里的提取失败。若学生刚见过 15²，不要把定义再讲一遍。

正确关系：`25² = 625`

记忆钩子：前面是 2。2 × 3 = 6，后面接 25，所以是 625。

规律：和 15² 同一条恒等式。这里把「前面的数加 1 再相乘」说清楚，避免学生以为永远是 1×2。

合理性检查：在 `20² = 400` 和 `30² = 900` 之间，以 25 结尾。

邻近例子：`15² = 225`，`35² = 1225`。

不要讲：重新定义平方，或把 15² 的步骤原样再念一遍而不换数字。

视觉线索：`2 × 3` → `6` → `625`。比 15² 少一帧，因为规律已经见过。

可选声音：不必。若开，只在 6 和 25 接上时一声。

把握：恒等式确定。是否在第二次就缩短反馈，待复核。

## 11.3 17 × 6

可能的错误类型：提取失败，或靠近整十时算错了差。例如把 120 − 18 算成 120 − 8。这是假设。

正确关系：`17 × 6 = 102`

记忆钩子：17 比 20 少 3。`20 × 6 = 120`，再减去 `3 × 6 = 18`，得到 102。这是分配律，不是口诀。

规律：靠近整十的数，可以先用整十，再补回差额。它是启发式的入口，底下是确定的等式。

合理性检查：在 `15 × 6 = 90` 和 `20 × 6 = 120` 之间，更靠近 120。个位 7 × 6 的个位是 2，所以答案个位应是 2。

邻近例子：`16 × 6 = 96`，`18 × 6 = 108`。

不要讲：末位是 5 的平方规律。不要把乘法重讲成「几个几相加」的长课。

视觉线索：120 旁边落下一小块 18，剩下 102。

可选声音：无。减法补偿不适合「接上 25」那种节奏，硬配会误导。

把握：等式确定。学生是否觉得「减 18」比直接乘更易记，待复核。

## 11.4 3/4 → 0.75

可能的错误类型：表示法混淆，例如写成 0.34，或把分子分母颠倒成大于 1 的数。假设，待复核。

正确关系：`3/4 = 0.75`

记忆钩子：一份的四分之一是 0.25。三份就是 `3 × 0.25 = 0.75`。

规律：四分之一这一家是 0.25、0.50、0.75。规则是 3 ÷ 4。屏幕上用四分之一这一家当钩子，除法留在设计笔记里。

合理性检查：比一半大，比 1 小。0.34 太小，1.33 太大。

邻近例子：`1/4 = 0.25`，`2/4 = 0.50`。

不要讲：小数的全部定义，或长除法竖式。

视觉线索：一条均分成四段，涂三段，旁边写 0.75。

可选声音：无。三段涂色本身已有顺序。

把握：0.25 × 3 确定。用「四分之一家族」而不是竖式，是教学选择，待复核。

## 11.5 1/8 → 0.125

可能的错误类型：表示法混淆，例如写成 0.8 或 0.18。假设，待复核。

正确关系：`1/8 = 0.125`

记忆钩子：连续取半。`1/2 = 0.5`，`1/4 = 0.25`，`1/8 = 0.125`。

规律：分母每次乘 2，小数就取半。这和 3/4 的「几份 0.25」不是同一个钩子。

合理性检查：比 0.25 小，比 0.1 大。0.8 是把分母当成了个位。

邻近例子：`2/8 = 0.25`，`4/8 = 0.5`。

不要讲：再把 3/4 的涂色条讲一遍，或展开二进制。

视觉线索：0.5 对折成 0.25，再对折成 0.125。

可选声音：两声对折。可选。文字里的两次「一半」已经够。

把握：取半链确定。0.125 的位数对初中生是否过长，待复核。

# 12. Open Questions

- 个位是 5 的钩子，学生是否真的比「再看一次 225」更记得住？需要人和孩子看。
- 25² 是否应该比 15² 更短，避免第二次还是一篇小课？
- 17 × 6 用「20 减去 3」是否比直接分解 `10 × 6 + 7 × 6` 更好记？
- 3/4 用 0.25 家族，还是允许一次短除法？本候选选了家族。
- 声音完全不做，还是以后只在反馈里做可选节奏？
- 记忆线索用 CSS / SVG 就够，还是以后某个物体值得 Three.js？现在不决定。

# 13. Risks

- 把每个错题都教成小课，认知负荷会盖过提取练习。
- 不可靠的口诀一旦写进界面，会比没有提示更糟。
- 动画和声音若出现在做题页，会打断提取。
- 五个样例被当成全部题库的模板。它们不是内容契约，也不能套用到所有题。
- 邻近例子若太多，会变成另一张数表。

# 14. Items needing Owner / teacher review

- 五个钩子的教学效果，不是数学对错。
- 17 × 6 选哪一个补偿或分解。
- 3/4 是否接受「不写竖式」。
- 反馈里出现邻近例子，会不会被看成提前泄露别的题。本候选把它们当关系网络，不当下一题答案。
- 可选声音要不要进入以后的原型试验。本轮没有声音。

# 15. Motion and Three.js boundary

三档：

| 时刻 | 动作 |
| --- | --- |
| 首页 | 好奇、轻空间、物体可以轻微悬停 |
| 做题 | 几乎静止 |
| 反馈 | 一段短记忆动画，只讲一个点 |
| 完成 | 很轻的收束 |

不要焰火、连击、循环噪音，也不要在计算时播放。

Three.js 未批准实现。

`VISUAL / LEARNING CONCEPT ONLY`

以后若某个数学对象值得立体操作，例如面积块、分数条、几何关系，再由架构在 CSS、SVG、Canvas、Three.js / WebGL 之间选。选择标准是学习价值和设备性能，不是「有 3D 更高级」。
