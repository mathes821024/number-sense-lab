# 1. 设计立场

这份课程不是一张电子版大九九表。它回答的问题是：

> 哪些数字关系值得直接记住，哪些值得会推导，哪些只需要建立数量感——以及怎样让普通初中生把它们留在脑子里。

两个基本原则贯穿全部三个域：

**完整知识地图 + 分层掌握要求。** 「没有进入核心训练集」不等于「知识库里不存在」。每个域先建立完整的知识版图，再从中筛选不同掌握层级。知识世界可以是完整的，训练要求必须是有选择的。

**Natural Structure First，Mnemonic Second。** 记忆方法优先使用数学本身的结构；其次是关系网络和锚点；再次是合理性判断和视觉辅助；人工口诀是最后手段，且永远不允许比原计算更复杂。没有好技巧的关系，诚实标记为 Retrieval Anchor（提取锚点），靠间隔提取记牢。

# 2. 统一分层模型

三个域共用同一套四层模型：

| 层级 | 含义 | 学习目标 | 是否进入 v0.1 训练 |
| --- | --- | --- | --- |
| Core Recall | 核心直接提取关系 | 不看表直接想起来，跨天稳定 | ✅ 唯一进入抽题、mastery、A4 打印的层 |
| Structured Practice | 结构可推导关系 | 借助规律、变换或锚点快速推出 | ❌ v0.1 不出题；作为反馈中的相关例和后续扩展池 |
| Recognition / Estimate | 认识与估算关系 | 能判断数量级、结果是否合理 | ❌ v0.1 不出题；用于合理性检查教学 |
| Knowledge Map | 领域完整知识版图 | 看得到全貌 | ❌ 不进 UI；是内容资产和后续扩展的母体 |

v0.1 的抽题队列、熟练状态（未练 / 学习中 / 稳定 / 动摇）、A4 打印只作用于 **Core Recall** 层。这一设计保证：

- PRD「每个域不超过 40 个关系」的内容契约被严格满足——它约束的是可训练关系，三个域的 Core Recall 分别为 16、32、27 条；
- 25²、35² 这类关系可以合法地「存在于系统里」——作为 15² 反馈中的 supporting example 或知识地图条目，而不是可训练关系、mastery 对象或抽题对象；
- 将来扩展（进阶挑战、新域）时，内容从知识地图里「升级」即可，不需要重做内容体系。

**trainable relation 与 supporting example 的判别规则**：一条关系是 trainable，当且仅当它作为独立记录出现在 `content/v0.1/*.core.json` 中。出现在 `pattern.family`、知识地图、课程文档任何其他位置的关系，一律是 supporting example，不得进入抽题与 mastery。

# 3. 平方域（Squares）

## 3.2 Core Recall 的构成与教学逻辑

16 条核心关系不按数字顺序组织，而按**提取策略**分三波（tier）：

**Tier 1｜即取层（7 条）**：6²、7²、8²、9²、10²、15²、20²——小九九内（6²–9²）、整十（10²、20²）、尾 5 规律（15²）。钩子最强、成功率最高，用于建立信心，是首次训练的入口波次。

**Tier 2｜结构层（6 条）**：11²（借 10²）、12²（提取锚点）、13²/14²（末位自检）、16²（提取锚点，2⁸ 网络在拓展层）、25²（尾 5 规律再现）。

**Tier 3｜锚点层（3 条）**：17²（诚实锚点）、18²、19²（借 20² 回算）。初始难度最高，最后进入。

## 3.3 范围说明

Core Recall = 6²–20² + 25²。其中 6²–20² 是 PRD 已冻结的默认范围；25² 进入 Core Recall 已经 Owner / ChatGPT 批准（FIX 01 Q1），理由是：625 复用价值较高、尾 5 结构价值高、与 15² 形成规律对。**Content Freeze 前需做一次小型 PRD 对齐修订**（默认平方范围 6²–20² → 6²–20² + 25²），属产品契约小修订，需 Owner 授权后执行，详见 REVIEW_REPORT 第 9 节。

1²–5² 不进入训练队列（与 PRD 一致），在知识地图中标记为 Structured Practice（小九九内，直接可得）。

# 4. 常用乘积域（Selected Useful Products）

## 4.1 候选池与精选

候选池为 6–19 范围内的全部数对（6 ≤ a < b ≤ 19，交换不重复计，平方归平方域），共 91 对，见 `content/v0.1/products.knowledge_map.json`。从中精选 **32 条**进入 Core Recall，遵守 PRD 上限（≤40），且明确不是 6–19 的完整笛卡尔积。

## 4.2 精选逻辑（选条标准）

每条入选关系必须命中以下至少一类证据，逐条理由见 `02_content_inventory.md`：

1. **后续计算复用价值**：在因式分解、十字相乘、约分通分等后续计算中复用价值较高（如 12×7=84、13×14=182）。此类频次判断属课程设计假设，待真实使用数据验证（FIX 01）；
2. **后续代数价值**：预演代数恒等式或结构（如 14×16 = 15²−1 预演平方差）；
3. **结构代表性**：代表一类可迁移的规律（×11 两头拉、偶数×15 减半×30）；
4. **关系网络价值**：与已掌握关系串成网（16×8=128 接 2 的连乘家族；91=7×13 接「假质数」辨别）；
5. **降低工作记忆负担**：记住它能给后续多步计算腾出工作记忆。

不因任何现成数表中存在而入选；不沿用任何现成资料的分族与命名。

## 4.3 结构分组（教学组织，非数据分族）

- **×11 簇（5 条）**：11×12、11×13、11×15、11×16、11×19。结构钩子「两头拉开，中间放和」，11×19 专练进位情形。
- **×15 簇（5 条）**：15×6、15×8、15×12、15×14、15×16。变换钩子「偶数减半再 ×30」，并在反馈中给出 10n+5n 的互证算法。
- **×12 簇（6 条）**：12×6–12×9、12×13、12×14。因式分解最高频的一组。
- **13×、14× 簇（7 条）**：13×6–13×9、14×7–14×9。含 91=7×13（假质数辨别）、14×7=2×49（借平方）。
- **16–19×一位数（4 条）**：16×8（2⁷ 关系网）、17×8（锚点）、18×9=2×81（借平方）、19×8（借 20 回算）。
- **十几×十几（3 条）**：13×14、13×15、14×16（平方差预演）。
- **6×十几（2 条）**：17×6、19×6。

波次：Tier 1（4 条）为 15×6、15×8、12×6、12×7；Tier 2（15 条）为主体；Tier 3（13 条）为十几×十几与进位、借算类。

# 5. 分数 → 小数域（Fraction → Decimal）

## 5.1 知识地图

覆盖分母 2、4、5、8、10、20、25 的全部最简真分数，共 43 条，见 `content/v0.1/fractions.knowledge_map.json`。全部为有限小数；循环小数（分母 3、6、7、9、11、12、15…）按 PRD 排除，连同「小数 → 分数」方向一起进入 `99_future_backlog.md`。

## 5.2 Core Recall（27 条）

| 分母 | 入选 | 数量 | 教学逻辑 |
| --- | --- | --- | --- |
| 2 | 1/2 | 1 | 地基锚点 |
| 4 | 1/4、3/4 | 2 | 1/2 对半得 1/4，3/4 是它的三倍 |
| 5 | 1/5–4/5 | 4 | 1/5=0.2 锚点 + 倍数 |
| 8 | 1/8、3/8、5/8、7/8 | 4 | 1/8=0.125 锚点 + 倍数与「1 减锚点」 |
| 10 | 1/10、3/10、7/10 | 3 | 十分之几直写，最低成本 |
| 20 | 1/20、3/20、7/20、9/20、11/20、13/20 | 6 | 变换钩子：同乘 5 凑 100 |
| 25 | 1/25、2/25、3/25、4/25、6/25、8/25、12/25 | 7 | 变换钩子：同乘 4 凑 100 |

去重规则：只收最简分数（2/4、5/10、4/20 等不入选，它们与已收关系等价）。非核心但最简的关系（如 9/10、17/20、7/25–24/25 中其余）留在知识地图的 Structured Practice 层，共用同一变换钩子，作为后续扩展池。

## 5.3 教学主线

本域只教**两个动作**，覆盖全部 27 条：

1. **锚点倍数**：1/4、1/5、1/8、1/10 四个锚点记牢，同族其余是「几个锚点」或「1 减锚点」；
2. **凑百变换**：分母 20 同乘 5、分母 25 同乘 4，把分数转成百分之几。

这条主线同时为百分数学习埋下迁移路径（0.35 = 35%），但百分数本身不进入 v0.1。

# 6. 学习顺序与波次

**域间顺序**：三域并行，不先后解锁。今日训练按产品契约从三域的未稳定关系中混抽（交错练习，interleaving，正是长期保持的优选排布）。

**域内顺序**：用 tier（波次）表达，不改变产品机制：

- Tier 1 是「入口关系」——首次使用的前几节优先遇到，钩子最强、成功率最高，对应 PRD 待验证问题 2「从少量入口关系开始」的建议；
- Tier 2 是主体，在入口关系普遍进入「学习中」后自然通过抽题队列浮现；
- Tier 3 是初始难度最高或最依赖前置关系的内容，最后进入。

**Content Tier ≠ Review Interval（FIX 01）**：tier 只表达内容进入顺序与初始教学建议，不决定复习间隔。真正的复习调度由运行时根据这个学生的作答对错、稳定状态、跨天表现动态决定，属 Technical Design，不在本契约冻住。

**两周节奏预期**：三域合计 75 条 Core Recall，按每天 5–10 分钟、每节约 15–25 题（含错题再现）估算，两周内每条关系可被跨天提取 3–6 次，与 PRD「大约两周的每天练习里被重复遇到」的设定一致。

# 7. 与产品机制的接口

| 产品机制 | 内容层提供什么 |
| --- | --- |
| 抽题队列 | `*.core.json` 的 75 条 trainable relation + tier |
| 判题 | `canonical_answer` + `answer_type`（integer / decimal）。按数学等价值判题：0.5 = 0.50 = .5，289 = 0289（FIX 01 Q2 已批准）；由统一 answer normalization 规则实现，不在内容数据中逐条枚举等价形式；展示统一用 canonical_answer |
| 答错反馈 | `relation`（一级）→ `hook`（二级）→ `pattern` + `frames`（三级，学生主动展开） |
| 错题再现 | 无内容层特殊处理，按产品规则 |
| A4 打印 | 当前不稳定关系 = Core Recall 中状态为学习中/动摇者 |
| 进度页 | 同上，内容层不新增展示 |

内容层不提供、也不要求：新页面、新题型、对照表、知识地图 UI、一步应用题。知识地图在 v0.1 是纯数据资产。

# 8. 一步应用的处理

按 Owner Decision，一步应用（如「边长 15 的正方形面积」）**不进入 v0.1 active content**。本契约仅在 `99_future_backlog.md` 记录其迁移价值与候选形式，不进入 `content/v0.1/` 运行数据。v0.1 聚焦直接关系提取。
