# 2. Relation Family（关系族）规格

## 2.1 定义

Relation Family 是**内容层结构**：一组数学上紧密关联的 relation。它：

- **不是**新的掌握对象（掌握仍按单条 relation 四态）；
- **不是**新的调度桶（调度仍按 relation id + schedule）；
- **不是**新的错题本分册（错题本按 id 自动归入）；
- 用于两件事：内容组织（课程文档、知识地图），以及洗牌约束（同族不连成串，见第 7 节）。

## 2.2 数据字段（最小新增，不推倒 v0.1 JSON）

在 relation 记录上增加**可选**字段 `family`。v0.1 现有 75 条不加此字段也合法；本轮涉及的关系按下表补齐。

```json
"family": {
  "id": "sq-15",
  "type": "inverse_pair | cyclic_rotation | scaling",
  "role": "forward | inverse | member",
  "counterpart": "isquare-15"
}
```

- `inverse_pair`：互为逆的两条 relation（如 `square-15` ↔ `isquare-15`）。`counterpart` 填对方 id。
- `cyclic_rotation`：循环节轮转族（1/7 族）。
- `scaling`：同一锚点的倍数族（1/3 族、1/9 族、v0.1 的 1/8 族等）。
- 族 id 命名：平方逆对 `sq-<n>`；分数逆对 `fr-<num>-<den>`；1/7 族 `cyc-7`；1/9 族 `ninths`；1/3 族 `thirds`。

## 2.3 三种族类型与数学事实

| 族 | 数学事实 | 教学含义 |
| --- | --- | --- |
| 平方逆对 | n² = m ⟺ √m = n（m 为完全平方数，取正根） | 正向稳定后，反向是「再编码」而非新知识 |
| 分数逆对 | a/b = d（有限小数）⟺ d = a/b | 双向提取同一锚点 |
| 1/7 轮转族 | 1/7=0.(142857)，2/7=0.(285714)…同一循环节 142857 轮转 | 记一圈，得六条；但轮转本身对初一偏难，见第 5 节分层 |
| 1/9 族 | n/9 = 0.(n)（n=1..8） | 规律极强，1/9 是锚点 |
| 1/3 族 | 1/3=0.(3)，2/3=0.(6) | 余数恒为 1 导致循环 |

# 4. 小数 → 分数（这个小数是哪个分数）

## 4.1 第一刀范围

**建议：恰好覆盖现有 27 条 Core Recall 分数→小数的逆，共 27 条。** 理由同 3.1：逆提取应以正向稳定为前提；27 条保持族双向完整，不多不少。新家族（1/3、1/9、1/7）的逆向本轮**不做**，待正向稳定后再评估（见第 5.5 节）。

## 4.2 问法

- prompt：`0.125 是哪个分数？`；存储写 `0.125`，给学生看的分数用横线分数。
- canonical_answer：最简分数字符串 `1/8`；answer_type：`fraction`；新增 `direction: "inverse"`；domain：`fraction_decimal`。
- tier = 正向 tier + 1（封顶 3）。

## 4.3 判题规则（待 Owner 确认 D1：最简分数唯一接受）

**建议：只接受最简分数。** 0.5 只接受 `1/2`，不接受 `2/4`。

理由：

1. **判题必须有唯一标准形式。** 接受等价分数意味着接受无穷多个答案（2/4、3/6、50/100…），判题从「对照标准形式」退化成「值相等 + 额外规则」，边界永远说不清。
2. **最简是校内既有约定。** 初中对「分数结果要约到最简」有明确要求，本工具与校内要求一致，不制造两套习惯。
3. **数感目标是规范表征。** 0.5 ↔ 1/2 是一条关系；0.5 = 2/4 是计算，不是本工具要训练的提取对象。

反例与处理：学生答 `2/4`（值对但未最简）——

- 判为**不正确**（规则已事先告知），但反馈与「值错误」区分开：
- 反馈语：`2/4 和 1/2 一样大，约到最简是 1/2。`（给出正确关系，不羞辱，符合反馈原则。）
- 这条作答按既有答错规则进入调度；它仍然是一次「没答出目标关系」。

工程注意：判题为「值相等 ∧ 已最简」两个条件；值不等 → 普通答错反馈；值等但未最简 → 上述专用反馈。不允许把 `2/4` 静默判对。

# 5. 循环小数与三个新家族

## 5.1 循环小数：一种写法，三层说清（待 Owner 确认 D3）

**学生看见的写法（唯一正式记法）：括号循环节记法。**

```text
1/3 = 0.(3)
2/3 = 0.(6)
1/9 = 0.(1)
1/7 = 0.(142857)
```

**系统存储的答案（canonical_answer）：同一字符串**，如 `"0.(3)"`、`"0.(142857)"`。answer_type：`decimal_repeating`。展示层（UI）以后可以把 `0.(3)` 渲染成上加点的形式，但内容层字符串与判题都以 `0.(3)` 为准，不并列第二套正式答案。

**怎样判对（normalization 规则）：**

学生键盘只有数字和小数点，因此接受以下输入，规范化后与 canonical 等价：

1. 括号形式 `0.(3)`（若将来键盘加括号键；本轮不依赖新键）；
2. **纯数字「循环节完整重复至少 2 次，末尾可再跟循环节的一个前缀」**：
   - 1/3：`0.33`、`0.333`、`0.3333`… ✅
   - 1/7：`0.142857142857`、`0.1428571428571`… ✅
   - 不足两个完整循环节（`0.3`、`0.142857`）→ **不判错**，停在原题，提示「把循环节再写一遍」（与空答案同一处理，不进错题、不改状态）；
   - 循环节写错（`0.142587…`）→ 判错，正常反馈。

接受「重复两遍」而非「一遍」的理由：写两遍才能证明学生掌握的是**循环**而不是一个有限小数；0.3 与 1/3 在数值上并不相等，判对必须基于记法约定而非近似。1/7 要输入 14 位数字，负担真实存在——这正是它排 tier 3 的原因；frames 会把 142857 分组成 `142 | 857` 帮助分块。

被拒绝的备选：① 只接受括号形式——需要给键盘加括号键，改动 UX 答案区，成本高于收益；② 接受「写到某精度即算对」（如 0.33 即对）——与「不足两遍不判错」相比边界更模糊，且把 0.3 判对会混淆 1/3 与 3/10。

# 6. Memory Hook 与 Visual Chain

**Visual Chain 就是现有 `frames` 字段，本轮不新增字段。**

- v0.1 已定：`hook`（一句）、`pattern.check`（规律+合理性）、`pattern.family`（相关例）、`frames`（2–4 步分步画面）。frames 即视觉链的载体，按 relation id 从内容层读取，不写进学习者档案（与 state v3 第 8 节一致）。
- 本轮所有新关系沿用同一 schema，仅 `frames.detail` 中允许出现 `0.(3)` 记法。
- 循环小数 frames 示例（fraction-1-7）：

```json
"frames": [
  { "title": "1 ÷ 7", "detail": "余数开始循环" },
  { "title": "142 | 857", "detail": "循环节分两块记" },

```

- Hook 质量红线不变：数学上成立；结构优先；没有可靠结构就诚实标提取锚点（isquare-12、isquare-16 即如此）；不发明比原计算更难的口诀。「走马灯数」是 142857 的经典名称，作为 Level 3 的 relation network 素材使用，不作为必背口诀。

# 7. 学生会看到的顺序约束

1. **族有结构，练习不能按族往下背。** 沿用已冻结的受控洗牌：同一优先级内打散，禁止相邻数连出、禁止同族连成串、禁止完全随机。
2. **inverse_pair 成员视为同一关系族。** 正向 `square-15` 与反向 `isquare-15` 不得在同一节相邻出现（答案互相泄露）。这一条不新增调度规则——它落入已有的「同一关系族连成一串」禁令，只需洗牌实现把 family.id 纳入「族」的判定。标注：实现细节属 Technical Design。
3. **进入顺序建议（非调度规则，待确认 OQ3）：** 反向关系的 `tier` 已比正向 +1；进一步建议未练反向关系在对应正向达到 `stable` 之前不进入候选。建议以可选内容字段 `"entry_after": "square-15"` 表达，解释归 Technical Design；不实现前不影响任何现有行为。
4. 今日训练仍三个域轮流；反向关系与正向同域（squares / fraction_decimal），不产生第四个域，调度轮流结构不变。
