# 2. Relation Family（关系族）规格

## 2.1 定义

Relation Family 是**内容层结构**：一组数学上紧密关联的 relation。它：

- **不是**新的掌握对象（掌握仍按单条 relation 四态）；
- **不是**新的调度桶（调度仍按 relation id + schedule）；
- **不是**新的错题本分册（错题本按 id 自动归入）；
- 用于两件事：内容组织（课程文档、知识地图），以及洗牌约束（同族不连成串，见第 7 节）。

## 2.2 数据字段（最小新增，不推倒 v0.1 JSON）

在 relation 记录上增加**可选**字段 `families`（数组）。**一条 relation 可以同时属于多个关系族**——例如 `fraction-1-8` 既属于与 `ifraction-1-8` 的 `inverse_pair`，也属于 1/8 倍数族 `eighths`（scaling）；未来的循环小数反向关系也可能同时挂 `inverse_pair` 与 `cyclic_rotation`。若冻成单个族对象，以后必然还要改 schema，本轮直接定为数组。

```json
"families": [
  {
    "id": "fr-1-8",
    "type": "inverse_pair",
    "role": "forward",
    "counterpart": "ifraction-1-8"
  },
  {
    "id": "eighths",
    "type": "scaling",
    "role": "member"
  }
]
```

- 旧内容字段缺省或 `"families": []` 均合法；不为加字段而重写现有 75 条，relation id 保持不变。
- `inverse_pair`：互为逆的两条 relation（如 `square-15` ↔ `isquare-15`）。`counterpart` 填对方 id。
- `cyclic_rotation`：循环节轮转族（1/7 族）。
- `scaling`：同一锚点的倍数族（1/3 族、1/9 族、v0.1 的 1/8 族等）。
- 族 id 命名：平方逆对 `sq-<n>`；分数逆对 `fr-<num>-<den>`；1/7 族 `cyc-7`；1/9 族 `ninths`；1/3 族 `thirds`；1/8 族 `eighths`。
- 同族判定（洗牌用）：两条 relation 的 `families` 中**任一**族 id 相同，即视为同一关系族。

## 2.3 三种族类型与数学事实

| 族 | 数学事实 | 教学含义 |
| --- | --- | --- |
| 平方逆对 | n² = m ⟺ √m = n（m 为完全平方数，取正根） | 正向稳定后，反向是「再编码」而非新知识 |
| 分数逆对 | a/b = d（有限小数）⟺ d = a/b | 双向提取同一锚点 |
| 1/7 轮转族 | 1/7=0.(142857)，2/7=0.(285714)…同一循环节 142857 轮转 | 记一圈，得六条；但轮转本身对初一偏难，见第 5 节分层 |
| 1/9 族 | n/9 = 0.(n)（n=1..8） | 规律极强，1/9 是锚点 |
| 1/3 族 | 1/3=0.(3)，2/3=0.(6) | 余数恒为 1 导致循环 |

# 4. 小数 → 分数

## 4.1 第一刀范围

**建议：恰好覆盖现有 27 条 Core Recall 分数→小数的逆，共 27 条。** 理由同 3.1：逆提取应以正向稳定为前提；27 条保持族双向完整，不多不少。新家族（1/3、1/9、1/7）的逆向本轮**不做**，待正向稳定后再评估（见第 5.5 节）。

## 4.2 问法

- prompt：`0.125 = ?/?`。训练屏把 `?/?` 画成两格和一条横线，不把这四个字符原样印在题干上。
- canonical_answer：最简分数字符串 `1/8`；answer_type：`fraction_fields`；`direction: "inverse"`；domain：`fraction_decimal`。`1/8` 是数据，不是学生界面。
- tier = 正向 tier + 1（封顶 3）。

## 4.3 判题规则（Owner 已拍板 D1：canonical 只认最简，等值未约分单列语义）

**Canonical answer 只认最简分数。** 0.5 的掌握目标只有 `1/2`。理由：

1. **判题必须有唯一标准形式。** 接受等价分数意味着接受无穷多个答案（2/4、3/6、50/100…），判题从「对照标准形式」退化成「值相等 + 额外规则」，边界永远说不清。
2. **最简是校内既有约定。** 初中对「分数结果要约到最简」有明确要求，本工具与校内要求一致，不制造两套习惯。
3. **数感目标是规范表征。** 0.5 ↔ 1/2 是一条关系；0.5 = 2/4 是计算，不是本工具要训练的提取对象。

**但「值对未约分」不与「数值错误」同等对待（Owner D1 修订）。** 判题结果定义为三种语义：

| 结果 | 条件 | 处理 |
| --- | --- | --- |
| `correct` | 值相等 ∧ 已最简 | 正常判对 |
| `needs_simplification` | 值相等 ∧ 未最简（如 0.5 → `2/4`） | 反馈：`2/4 和 1/2 一样大，再约到最简：1/2。` **不计为普通答错，不产生 mistake evidence** |
| `incorrect` | 值不相等（如 0.5 → `3/5`） | 普通答错，按既有规则进入调度与错题证据 |

数学上 `2/4 = 1/2`，孩子的理解是对的，只是答案形式还没完成——这不能和「完全不知道 0.5 是什么分数」混成同一种学习证据，否则违背「记录真实学习状态」的原则。同时不允许把 `2/4` 静默判对：canonical 掌握目标仍是 `1/2`。

运行时契约变化（记录在此，实现归 Technical Design）：判题结果枚举从两值扩展为 `correct / needs_simplification / incorrect`；`needs_simplification` 不判对、不推进掌握、不进错题本、不计普通错误。是否让学生当场改答为约分形式属交互细节，由 Technical Design 决定，本规格只冻结上述语义。

# 5. 循环小数与三个新家族

## 5.1 循环小数：存储一种写法，学生看见循环点（Owner 已拍板 D3，显示按 v0.3 体验修订）

**系统存储的答案（canonical_answer）**仍是括号字符串，如 `"0.(3)"`、`"0.(142857)"`。answer_type：`decimal_repeating`。判题只比这套字符串。内容不因显示而迁移。

**学生看见的写法**是教材里的循环点，不是括号。一位循环时，点标在这个数字上方。多位循环时，点标在循环节第一位和最后一位上方，例如 `0.142857` 的 `1` 和 `7` 上方各一点，表示整段 `142857` 循环。反馈、正确关系、规律和答案框用同一种显示。不并列第二套正式答案。

**怎样判对（Repeating Decimal Input 循环节输入模式）：**

学生只看到小数和循环点。学生**只输入循环节**：

| 题 | 学生输入 | 拼成 |
| --- | --- | --- |
| 1/3 = ? | `3` | 0.(3) |
| 2/3 = ? | `6` | 0.(6) |
| 1/9 = ? | `1` | 0.(1) |
| 1/7 = ? | `142857` | 0.(142857) |

- 不需要括号键；不需要输入两遍；1/7 只输入 6 位数字。
- 判题边界明确：输入的循环节与 canonical 的循环节**精确相等**才判对；循环节写错（`142587`）或写成同族另一成员的循环节（`285714`，那是 2/7）→ 普通答错，正常反馈。
- 这样测的是 `1/7 ↔ 142857` 这条循环关系本身，而不是键盘耐心与抄写准确率——与「不要机械、不要枯燥」的反馈原则一致。

运行时 / UX 契约：答案区是循环节输入。学生只打循环节，界面画循环点，不提供循环点键或括号键。存和判仍用 `0.( )`。

被否决的旧方案（留档）：本规格初版曾建议「纯数字输入、循环节完整重复 ≥2 遍才判对」（1/7 需输入 14 位）。评审否决：它测试的是键盘耐心而非循环关系。若未来循环节模式实现受阻，可作为降级方案重启评估，但不进入本轮冻结。

- 循环小数 frames 示例（fraction-1-7）：

```json
"frames": [
  { "title": "1 ÷ 7", "detail": "余数开始循环" },
  { "title": "142 | 857", "detail": "循环节分两块记" },
  { "title": "0.(142857)", "detail": "1/7 = 0.(142857)" }

```

- Hook 质量红线不变：数学上成立；结构优先；没有可靠结构就诚实标提取锚点（isquare-12、isquare-16 即如此）；不发明比原计算更难的口诀。「走马灯数」是 142857 的经典名称，作为 Level 3 的 relation network 素材使用，不作为必背口诀。

# 7. 学生会看到的顺序约束

1. **族有结构，练习不能按族往下背。** 沿用已冻结的受控洗牌：同一优先级内打散，禁止相邻数连出、禁止同族连成串、禁止完全随机。
2. **inverse_pair 成员视为同一关系族。** 正向 `square-15` 与反向 `isquare-15` 不得在同一节相邻出现（答案互相泄露）。这一条不新增调度规则——它落入已有的「同一关系族连成一串」禁令，只需洗牌实现把 `families` 中任一相同族 id 纳入「族」的判定。标注：实现细节属 Technical Design。
3. **`entry_after`（Owner 已拍板 OQ2：仅首次进入的解锁条件）：** 反向关系带可选内容字段 `"entry_after": "square-15"`。语义：**仅当反向 relation 从未练过（无任何作答记录）时**，要求 counterpart 达到 `stable` 才进入候选池；一旦反向 relation 有过任何作答，它就是独立 relation，按自己的 Scheduler 运转——之后正向即使答错变回 shaky，也不得把已学的反向题藏起来或重置。即：`entry_after` = unlock condition，≠ permanent dependency。反向关系的 `tier` 仍比正向 +1，两者叠加：tier 管大顺序，`entry_after` 管解锁时点。
4. 今日训练仍三个域轮流；反向关系与正向同域（squares / fraction_decimal），不产生第四个域，调度轮流结构不变。
