# v0.4 关系规格

状态：契约设计。这是以后写入内容文件时的唯一条目清单。现在不改 `content/` 下的 JSON。

每条共同字段：

| 字段 | 值 |
| --- | --- |
| `level` | `core_recall` |
| `answer_type` | `integer` |
| `direction` | `forward` |
| `entry_after` | 空 |
| `families` | 空数组，除第 6 节写明的 8 条 |
| `frames` | 恰好两帧。第一帧标题「这一步」，细节等于 `hook`。第二帧标题等于 `canonical_answer`，细节等于 `relation` |

`pattern.family` 里的句子是相关例，不是新的 relation id。禁止出现 id `pow-5-3`。

# 6. 关系族

只有这 8 条有 `families`。类型用已有的 `scaling`。没有新的族类型。

25 家族，id `f25`，role `member`：`sp-25-2`、`sp-25-3`、`sp-25-4`、`sp-25-6`、`sp-25-8`。

125 家族，id `f125`，role `member`：`sp-125-2`、`sp-125-4`、`sp-125-8`。

对象形状：

```json
{ "id": "f25", "type": "scaling", "role": "member" }
```

125 家族只把 `id` 换成 `f125`。一条 relation 只属于其中一族。
