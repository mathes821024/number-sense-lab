# 小数 → 分数：双输入契约

状态：双格输入已冻结。本节之后的前导 0 显示、位数和进度文案是一次轻量补充，不改判题。

它只改「小数 → 分数」的作答方式。分数 → 小数不变。补数题干的同步在 v0.4 规格里，不在这里重写内容。

`answer_type` 从 `fraction` 改为 `fraction_fields`。这个名字表示结构化的分子和分母，不是一整段自由文本。

PRD 第 13 节、`docs/curriculum/04_v02c_relation_families.md` 第 0 节和第 4 节、`docs/ux/02_ux_spec.md` 第 8 节已经改成同一条规则：小数 → 分数是两格，没有「/」键。其他题型也不出现「/」。

学生看得见的分数一律是分子在上、横线、分母在下。这包括训练题干、反馈、错题本、进度和 A4 题目页、答案页。文档、`canonical_answer`、判题字符串和技术日志可以继续写 `1/8`。那是数据，不是界面。没有「这个端画不出横线就改回斜线」的退路。

# 2. 学生看见的题

存储的 prompt 写成 `0.125 = ?/?`。训练屏不把 `?/?` 再画成一行字。

屏幕是：

```text
0.125 =  [ 分子 ]
          ─────
          [ 分母 ]
```

横线是分数线。上面一格是分子，下面一格是分母。不提供一个可以打出 `1/8` 的单行输入框，也不提供「/」键。

# 3. 输入

H5 和微信共用同一个分数输入组件。平台壳只负责把按键交给它。不各写一套分数格子。

- 进入题目时，焦点在分子。
- 点分子或分母，焦点移到那一格。
- 数字键只写进当前焦点格。只接受数字。没有小数点，没有负号，没有斜线。
- 退格只删当前格的最后一位。当前格已经空时，退格停在这一格，不跳到另一格。
- 提交看两格一起。电脑上 Enter 也是提交。提交键必须留在屏幕键盘这一屏里，不靠滚动才找得到。
- 物理键盘是 H5 的便利。微信不依赖物理键盘。两格都能只靠屏幕键盘做完。
- 在数字键上快速连点，记成按键，不把页面放大。不因此关掉整页缩放。

# 4. 什么时候算一次作答

两格在交给判题之前先收成一个字符串 `分子/分母`。空的、不合法的，不产生这个字符串，也不调用一次有效判题。

| 情况 | 结果 |
| --- | --- |
| 分子或分母还是空的 | 不是一次作答。停在这一题，提示「先写一个分数」 |
| 格里不是正整数 | 不是一次作答 |
| 分母是 0 | 不是一次作答 |
| 值不相等，例如 0.5 填了 3 和 5 | `incorrect` |
| 值相等但没约到最简，例如 0.5 填了 2 和 4 | `needs_simplification` |
| 值相等并且已是最简，例如 0.5 填了 1 和 2 | `correct` |

前导 0 按整数值判。`01` 和 `1` 是同一个数。`1/2` 判对。`2/4` 不判对，也不自动约成 `1/2`。

学生看见的格子不保留多余的前导 0。输入可以先收下 `0`，一旦后面出现非 0 数字，显示就去掉前面的 0。

- 按 `0` 再按 `2`，格子显示 `2`。
- 按 `0`、`0`、`4`，格子显示 `4`。
- 只按了一个 `0`，格子暂时显示 `0`。提交时它不是正整数，不记作答。
- 分母是 `0` 仍然不是一次作答。
- 这一步只去掉前导 0。`2/4` 保持 `2` 和 `4`，不自动变成 `1/2`。约分仍由学生完成。

例：题是 `0.5`。分子按 `0`、`2`，分母按 `0`、`4`。学生看见的是 `2` 在上、横线、`4` 在下。提交结果是 `needs_simplification`。

`fraction_fields` 服务的是常见短分数，不是任意精度计算器。正式内容里的合法分子和分母都是短整数，界面和字号按常见的一到三位来排。偶尔更长的值保持自然显示，不为极端长度把字缩小。

PRD、UX 和课程契约都不写「每格最多几位」。4 位、8 位、15 位都不是学习规则。运行时若另有技术保护，只留在代码注释和测试里，不写进学生看得见的文案，也不理解成「学生最多只能输入多少位」。以后若真要更大的整数，用字符串或 `BigInt` 来判，不把位数扩成课程规则。

换格靠点击分子或分母，见第 3 节。

做题进度不写成 `2 / 10`。那看起来像一道分数。学生看见的是「第 2 题 · 共 10 题」。这一节有几题、怎么选题，都不因此改变。

纸页上的空分数线留出手写的空，比屏幕上的格子更疏。仍是横线，没有斜线退路。

`needs_simplification` 沿用已有语义：不记成普通答错，不进错题本，不推进掌握，答案区不锁死。学生改完可以再交。反馈仍是「2/4 和 1/2 一样大，再约到最简：1/2。」这句话的意思。给学生看的分数用横线，不用斜线当主角。

答错仍停在正确关系上，再按「下一题」。正确关系画成最简分数的横线形式。没有「再做一遍」。

# 5. 错题本、进度、纸页

错题本和进度只显示题干，不显示答案。题干渲染成「0.125 =」加一条空的分数线，不写成一行 `1/8`，也不写成「是哪个分数」。

纸页规则不变：题目和答案不同页，黑字白底。题目页上，这类题是小数等于一条空分数线。答案页上，最简分数用横线分数。打印也没有斜线退路。

分数 → 小数的答案类型不变，仍用小数键盘。它的题干若存在存储写法 `1/8 = ?`，学生看见的 `1/8` 同样画成横线分数。

# 6. 存档

存储键仍是 `nsl-v01-state`。state 仍是 version 3。不升版本。

relation id 继续用原来的 `ifraction-*`。数学关系没变，所以不新开 id，也不把旧 id 迁到新 id。

作答记录的形状不变：只有 `correct` 和 `incorrect` 写入 `attempts`。`needs_simplification` 仍然不落一行。因此不为这次输入方式写迁移程序。

Owner 会自行清空已有学习记录。清空之后就是一份新的 version 3 空档，规则与现在的新设备空档相同。本契约不规定清空按钮的实现，也不读取旧的「1/8」字符串去改写成两次输入。

若清空没有发生，旧的 `attempts` 仍挂在同一个 id 上，不改写、不删除。那不是迁移。

# 8. 验收

- 27 条 `ifraction-*` 的 prompt 是 `0.125 = ?/?` 这种形式，`answer_type` 是 `fraction_fields`，`canonical_answer` 仍是最简分数字符串。
- 训练、反馈、错题本、进度、A4 题目页和答案页上的分数都是横线分数。学生界面没有「/」键，也没有斜线分数。
- H5 和微信使用同一个分数输入组件。
- 空格、非正整数、分母 0 不是一次作答。最简判对。等值未约简是 `needs_simplification`。

- 正式契约不写每格位数上限。界面按常见短整数排，不按超长整数缩小字号。
- 做题进度写成「第 2 题 · 共 10 题」，不写成 `2 / 10`。
- state 仍是 version 3，键仍是 `nsl-v01-state`。relation id 不变。旧 attempts 不改写。
