# 跨端前端架构

状态：供 A1 架构评审。不开始迁移，不改 V0.3 行为，不改学习契约。

方向已经写在 `docs/architecture/00_multi_client_direction.md`：一个核心，多个客户端。本文把「页面写在哪」定到可以评审的程度。框架取舍见 `docs/decisions/02_cross_platform_framework.md`。能力档位见 `docs/architecture/01_platform_capability_matrix.md`。

## 现在的代码说明了什么

`main` 上的 `src/core/` 不调用 `localStorage`、`document`、`window`、`wx`、`tt`、`my`。`test/architecture.test.js` 在守这条线。`src/adapter/browser-store.js` 才接触存储。判断、掌握、调度、错题含义都在核心里，并用 `node --test` 覆盖。

`h5/` 是浏览器壳：`app.js` 直接操作 DOM，答对后用 `window.setTimeout`，打印用 `window.print`，键盘用 `document` 监听。`h5/index.html` 在运行时请求 `fonts.googleapis.com`。`h5/math-text.js` 把分数拼成 HTML 字符串。这些都不能原样放进小程序。

公开的 V0.3 实现在 `feat/v03-concentrated-build`，是验收证据，不是第二套架构要求。

## 目标

```text
content/          题目与课程数据
src/core/         学习引擎，平台无关
app/components/   共用界面
app/theme/        语义主题，默认 math-lab
app/platform/     很薄的壳和适配
```

不追求四端一行不改。追求：学习结果只有一份实现；页面只有一套组件；平台差异只出现在适配层。

建议的最小目录，在垂直切片开工时再生效，现在不建：

```text
src/core/                 保持
src/adapter/              存储等接口的各端实现
app/pages/                首页、训练、答对、答错
app/components/           按钮、键盘、分数、循环小数、反馈
app/theme/                令牌和资产槽位
app/platform/h5/
app/platform/wechat/
app/platform/douyin/
app/platform/alipay/
assets/
content/
test/
```

`h5/` 先留着，当作行为参照。切片对上之后，它不再是长期主界面。

## 六层，各写什么

| 层 | 知道什么 | 不知道什么 |
| --- | --- | --- |
| 内容 | 关系、标准答案、记忆钩子 | 按钮和平台 |
| 核心 | 判断、掌握、调度、错题、会话 | `wx`、`tt`、`my`、`document`、`window`、框架 API |
| 共用界面 | 页面结构、题干、键盘、反馈 | 某个平台怎么存、怎么分享 |
| 主题 | 颜色、圆角、吉祥物槽位、装饰槽位 | 学习状态机 |
| 适配层 | 存储、音频、安全区、前后台、打印或保存、分享 | 哪一题对错 |
| 平台壳 | 该端的入口、编译配置、原生返回 | 另一套掌握算法 |

核心通过函数使用适配层，不在核心文件里写平台名字。

现在就该有接口的，只有切片用得到的：

- 存储：读、写、清空。语义与现在的浏览器存储相同。
- 音频：播放短提示、停止。关声音后什么都不播。
- 计时：答对后的短暂停顿。小程序切到后台要取消，不能把未提交的输入判错。
- 安全区：把顶部和底部留白交给布局。
- 打印或带出题目：H5 走系统打印；小程序以后走保存或分享。切片的四个页面可以先不接。

先不要建的：剪贴板、登录、支付、主题切换器。

## 共用界面规则

- 中文用系统字体。不在运行时加载 Google 字体，也不把 Nunito 的外链当成基线。
- 共用组件不使用没有退路的浏览器专有 CSS 或 DOM。
- 分数和循环小数由组件画出来。存储仍是 `1/2` 和 `0.(6)`。不把题目烤进图片，不用组合字符冒充循环点。
- 吉祥物和装饰只通过 `math-lab` 的语义槽位取。做题时不出现吉祥物。
- 平台 API 不出现在核心，也不出现在共用组件里。
- 新效果先标明 A、B 或 C。C 不能挡住小程序把这一题做完。
- 底部四个入口是共用组件。正在写答案时不渲染。

## 垂直切片

第一刀只做四屏，并且只要求两个端同时跑起来：

1. 首页
2. 训练
3. 答对
4. 答错

顺序是 H5 与微信。这两端都通过同一份核心测试和同一条手工路径之后，再加抖音，然后支付宝。

切片里必须仍是：一题一屏，答对短暂停顿后进入下一题，答错停在正确关系上并按「下一题」，没有「再做一遍」，没有倒计时。占位入口可以说「敬请期待」，但不做新业务。

留下不动的：`src/core/` 的判断、掌握、调度和现有测试；`content/` 的题目文件。

包一层的：存储。浏览器实现留在适配层，微信实现写成另一个文件，核心调用方式相同。

重写的：`h5/app.js` 的界面、`h5/styles.css` 的屏幕样式、`formatMath` 的 HTML 拼装。分数的拆分规则可以抽成纯函数再测，显示换成组件。

临时胶水：切片期间，`h5/` 继续能跑当前 V0.3，直到新壳的这四屏被接受。

以后可删的：被新 H5 壳替换掉的 `h5/app.js` 页面分支，以及运行时字体链接。

## 测试

| 层 | 看什么 | 何时必须有 |
| --- | --- | --- |
| 核心单测 | 同一输入得到同一判断、掌握变化和错题含义 | 现在就有，迁移不许改语义来迁就框架 |
| 适配契约 | 内存里的假存储满足读、写、坏 JSON 不覆盖 | 切片 |
| 共用组件 | 分数线、循环点、键盘提交把答案交给核心 | 切片 |
| H5 | 四屏能做完一题 | 切片 |
| 微信 | 同一四屏，开发者工具冒烟 | 切片 |
| 抖音 | 冒烟 | 微信切片通过之后 |
| 支付宝 | 冒烟 | 抖音之后 |

证明架构成立的是：同一组核心测试在不改断言的情况下继续通过，并且 H5 和微信用同一份页面代码走完「答对」和「答错」两条路径。

## 现有 H5 以后是什么

不是长期的共用客户端。小程序跑不了这套 DOM。

也不是现在就删掉。它是 V0.3 的行为参照。

目标是：新的共用界面编出 H5，当前 `h5/` 在四屏对齐后退出主路径。置信度：中。对齐标准要等切片，而不是今天估一个行数。
