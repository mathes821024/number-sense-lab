# 2. 目录登记不是新引擎

今天的目录把域名单和条数冻结成三个域、122 条。未知域会在计数检查里被拒绝。这是内容登记，不是调度规则。

BUILD 在放入新内容文件时，只把登记扩到已发布的域：

- 显示名：立方、半数与翻倍、补数、常见幂、凑整乘积家族。
- 轮流顺序：已有三域在前，其后按发布顺序接上新域。`pickAcrossDomains` 已经会把名单之外、但目录里存在的域排在已知域后面。不改这段轮流算法。
- 计数：已有三域仍是平方 32、常用乘积 32、分数到小数 58。新域整域发布时分别是 8、14、12、9、8。五域都发布时总数 173。旧的 122 条拆分不变。

不改 `scheduleAfterAttempt`、掌握四态、错题谓词、受控洗牌的禁则、打印「题目和答案不同页」。

断言「每日只有三个域」的测试，在新域进入目录后要改成「已发布的域都参与交错」。那是期望值更新，不是新的学习规则。
