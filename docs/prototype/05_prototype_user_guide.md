# Number Sense Lab 原型体验与学习指南

这份文档帮助你运行 PT0 原型、体验关键流程、记录反馈，并顺便理解项目里常见的 Git、前端和产品术语。

读者是 Owner、初中生、非前端专业的开发者，以及第一次接触产品原型的人。中文为主。英文词第一次出现时，会写成 English Term（中文解释），并且尽量用这个项目里的例子来讲。

---

# 1. 这是什么

Prototype（产品原型）是一份可以真的点、真的输入、真的答错的试验版。

它像装修前先看的样板间。样板间让你走进去，感觉门开得顺不顺、灯会不会刺眼、坐下之后还想不想再坐一会儿。它还不是你以后每天住的那套房子。

Number Sense Lab（数感训练场）现在的这份原型也是这样：

- 它让你和孩子先走一遍「开始练习 → 答题 → 看反馈 → 结束」。
- 它用来发现哪里顺、哪里别扭。
- 它还不是正式产品。
- 它还不是微信小程序正式版。
- 它也不是以后要长期维护的生产代码。

生产代码是指准备给很多人长期使用、出了问题要负责修好的那一版程序。现在这一版只为了体验。

PT0 里的 PT 是 Prototype，0 表示这是第一次原型验收。合在一起，PT0 = Prototype Gate 0（原型阶段的第一道门）。

Gate（阶段门）就是「这一段做完了，先停下来检查，通过了才进下一段」。前面已经走过治理、产品、体验和视觉几道门。这一道门看的是：人用起来到底怎么样。

通过这道门，靠的是你亲自点过之后的感觉，不只是程序能跑。

# 2. 怎么在自己电脑上打开

下面的步骤在 Mac 上直接可用。Windows 看下一节。

## 打开终端

Terminal（终端）是一个用文字发命令的窗口。Mac 上可以在「启动台」里搜索「终端」。

## 进入项目文件夹

仓库在你电脑上的位置如果是 `number-sense-lab`，就在终端里进入那个文件夹。文件夹的名字以你电脑上的为准。进入之后，你应该能看到里面有 `prototype` 和 `docs`。

这一层叫仓库根目录。后面的命令要在这里执行。

## 启动一个只给自己用的小服务器

复制下面这一行，粘贴到终端，按回车：

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

这几个词的意思：

| 你看到的 | 在这里是什么 |
| --- | --- |
| `python3` | 电脑上的 Python 3。Python 是一种编程语言。这里只借用它自带的一个小工具，不用写 Python 程序。 |
| `-m` | 让 Python 去运行后面那个模块，而不是去找一个单独的文件。 |
| `http.server` | Python 自带的迷你网页服务。它把当前文件夹里的文件，暂时变成可以在浏览器里打开的页面。 |
| `8765` | 端口号。可以把它想成这台电脑上的一扇小门。浏览器通过这扇门找到页面。8765 只是我们选的一个空门牌，没有特别含义。 |
| `--bind 127.0.0.1` | 只监听本机回环地址。这个临时页面不会开放给同一局域网里的其他设备。 |

终端停在那里、不再回到输入光标，通常表示这个小服务正在跑。先别关这个窗口。

## 用浏览器打开

Browser（浏览器）就是 Chrome、Safari、Edge 这一类用来看网页的软件。

在地址栏输入：

```text
http://127.0.0.1:8765/prototype/
```

`127.0.0.1` 和 `localhost`（本机）指的是同一件事：只访问你自己这台电脑，不是互联网上的一台服务器。旁边的人打不开这个地址，除非他们用的就是你这台电脑。

看到「数感训练场」，就可以开始体验。

用完之后，回到终端，按 `Ctrl + C`，小服务会停掉。下次想再看，重新执行那一行命令即可。

如果直接双击 `prototype/index.html`，有的浏览器会拦住页面里的脚本。遇到空白页或按钮没反应，就改用上面的地址。

# 3. Windows 上怎么打开

Windows 也可以用同一件事：一个本地静态服务器。静态的意思是，它只把现成的页面文件送出来，没有账号，也没有后台。

在项目文件夹里打开 PowerShell 或「命令提示符」，先试：

```bash
python -m http.server 8765 --bind 127.0.0.1
```

如果提示找不到 `python`，再试：

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

`--bind 127.0.0.1` 和 Mac 上一样：这个临时服务只留在自己电脑上。

然后用浏览器打开同一个地址：

```text
http://127.0.0.1:8765/prototype/
```

只要其中一条命令能让页面出现，就够了。不需要再安装别的框架或打包工具。

# 4. 怎么开始体验

先不要连着点。每一屏先停几秒，问自己一个感觉，再继续。

## 首页

打开后先看 3 秒。

问自己：

- 我不看说明，知不知道下一步该干什么？
- 这页像一张安静的练习纸，还是像考试系统？
- 有没有很多按钮在抢注意力？
- 「大约 5～10 分钟」让我更想开始，还是更想关掉？

然后点「开始今天的练习」。

## 做题

你会看到一道题、一个答案框，和一排数字键。手机上主要用这些键。电脑上也可以直接按键盘上的数字，再按 Enter 提交。

整数题没有小数点。像 `3/4 = ?` 这样的题，才会多出一个小数点。

观察：

- 题目是不是这一屏里最大、最清楚的东西？
- 数字键好不好点，会不会按错邻居？
- 什么都不填就按「提交」，页面会说「先写一个数。」这不算答错。

## 答对和答错

答对时，看「对」出现的那一下。答错时，先别急着点「下一题」，看自己的眼睛先落在哪里。后面第 5 节会把这两个场景分开做。

## 错题再出现

故意错一道，先做后面的题。那道错题会再回来一次。

观察：回来的时候，你觉得是「再练一道」，还是「它在抓我补错」？

## 快完成了

接近结尾时，原来写着「平方」或「常用乘积」的小标签，会改成「快完成了」。没有进度条，也没有「还剩 2 题」。

观察：你安不安心？你会不会很想知道还剩几道？

## 练完了

结束页上有一颗很小的星，主按钮是「先到这里」。

观察：你觉得今天可以停了，还是页面还在拉你再练？

## 最近练得怎么样

从结束页或首页进入。这是一张短列表：哪天做完了或先停了，对了几题、做了几题。

观察：它像学习记录，还是像成绩单？

这里的日期和「正在熟悉」是原型里准备好的例子，不是你刚才那几分钟真的算出的熟练程度。

## 印到纸上

看预览。纸上应该只有题目和留白，没有答案，也没有「错题」两个字。

观察：它像一张可以拿去写的练习纸，还是像一张答案表？

# 5. 请故意走这四个场景

样题不多。平方可以用 `12² = ?`，正确答案是 144。想看答错，就故意不要填 144。

## 场景 A：答对

填一个你确定的正确答案，提交。

观察：

- 「对」停留得刚刚好、太赶，还是你在等它走？
- 这一下有没有变成闯关、金币或连击？
- 你还想马上做下一题吗？

## 场景 B：故意答错

例如 `15² = ?` 填 `215`，提交。

先停几秒，不要马上点「下一题」。

观察：

- 你第一眼看的是正确关系，还是自己写错的地方？
- 正确关系够不够显眼？
- 有没有被批评、被打分的感觉？
- 看完之后，你还愿意点「下一题」吗？

这一题最重要。数感训练如果答错以后人不想继续，后面的功能都还早。

## 场景 C：中途停

做到一半，点「先停一下」。

观察：

- 「先停在这里？已经做的会留下。」让你安心，还是像在办退出手续？
- 「继续做」和「先停」哪一个更像你真正想按的？
- 有没有「任务失败」「今日未完成」这种压力？

先停之后回到首页，再点「继续刚才的练习」。如果刚才已经提交并且正在看对错，继续后应该还是那个反馈，而不是把同一题再答一次。

## 场景 D：做完

一直做到「练完了」。

观察：

- 这是「今天可以停了」？
- 还是「系统还想让我再开一段」？
- 那颗星是轻轻的完成标记，还是奖状？
- 「再练一小段」会不会比「先到这里」更抢眼？

# 6. 比较两种做法的地址参数

Prototype Parameter（原型参数）是加在地址后面的试验开关。它不是正式功能，也不是以后小程序里的菜单。它只是让你不用改程序，就能比较两种感觉。

改完地址后按回车，页面会按新的开关重新打开。

## 答对后停多久

Correct Delay（答对后的停留）用毫秒计。

ms = millisecond（毫秒）。1000ms = 1 秒。所以：

- 400ms 大约是 0.4 秒
- 550ms 大约是半秒多一点
- 700ms 大约是 0.7 秒

三个地址：

```text
http://127.0.0.1:8765/prototype/?correctDelay=400
http://127.0.0.1:8765/prototype/?correctDelay=550
http://127.0.0.1:8765/prototype/?correctDelay=700
```

各答对一次。哪一档你来得及感到「对了」，又不会觉得在等？

## 错题再出现时说不说「再试一次」

Revisit（再次出现）有两种：

```text
http://127.0.0.1:8765/prototype/?revisit=A
http://127.0.0.1:8765/prototype/?revisit=B
```

- A：错题回来时，看起来像一道普通新题。
- B：原来写域名的地方，改成「再试一次」。

问自己，也问孩子：「再试一次」是在鼓励，还是在提醒「你刚才错了」？

## 要不要看见刚才写错的数

Wrong Show（错答怎么显示）有两种：

```text
http://127.0.0.1:8765/prototype/?wrongShow=A
http://127.0.0.1:8765/prototype/?wrongShow=B
```

- A：不显示你刚才写的数，只留下原题和正确关系。
- B：用比较淡的字写「你刚才写：…」，正确关系仍然更大。

问自己：看见自己写错的数，是帮助明白差在哪里，还是多一份不舒服？

## 几个开关写在同一个地址里

可以这样：

```text
http://127.0.0.1:8765/prototype/?correctDelay=550&revisit=A&wrongShow=A
```

`?` 表示「从这里开始是给这一页的开关」。`&` 表示「还有下一个开关」。不需要把网址学成一门课，会改这三个数就够用。

另外三个开关，方便你重看某种首页或打印，也不是正式功能：

- `?home=first`、`?home=done`、`?home=paused`：第一次打开、今天练完、上次没做完
- `?fresh=1`：进度页变成「还没有练习」
- `?printEmpty=1`：打印页变成「现在没有需要印的题」

# 8. 这是程序坏了，还是设计要改

四类问题，处理的人不同。先分清，再决定改哪里。

## Bug（程序错误）

程序没有按已经说好的样子工作。

在这个项目里，例如：

- 数字键点了没反应
- 填了 144，`12²` 却被判错
- 页面卡住，按钮按不动
- 答错之后，刷新一下，同一题又能重新答

## UX Problem（交互体验问题）

程序能用，但人不知道下一步，或者走着走着不想走了。UX 是 User Experience（使用者的经历和感受）。

例如：

- 首页看了 3 秒，还是不知道该点哪里
- 答错以后不想按「下一题」
- 结束页像还没结束
- 「再试一次」让人觉得被追着罚

## UI Problem（视觉问题）

流程没变，但看起来不清楚或不舒服。UI 是 User Interface（人看到和点到的那一层）。

例如：

- 字太小，横过来看不清题目
- 错误那一块暖纸色太淡，不知道该看哪里
- 电脑上的数字键比题目还抢眼
- 结束页的星太像奖杯

## Product Problem（产品问题）

不是某一页画坏了，而是这件事本身值不值得做、做成什么样。

例如：

- 孩子根本不想每天练几分钟
- 「大约 5～10 分钟」一听就觉得太长
- 平方、常用乘积、分数到小数，这三块不合适

遇到后三类，先记在反馈里。不要在原型里悄悄把产品、体验或视觉改掉。那些规则写在另外的契约文档里，要经过评审才改。

# 9. 项目里的词

下面只收这个仓库里真的出现过的词。每个词都短，并且连着 Number Sense Lab 来讲。

## Git 和协作

Git（版本记录工具）记住每一次修改。可以回到从前，也可以看出是谁、为什么改的。

Repository / Repo（仓库）是这个项目的全部记录。GitHub 上的 `number-sense-lab` 就是仓库。GitHub 是存放仓库的网站。

Branch（分支）是从主线临时分出去的一条工作线。`prototype/v01` 就是「只做原型」的那一条。

`main`（主分支）是大家公认的当前正式版本。新想法先在分支上做，不直接改主分支。

Commit（一次有记录的修改）像存档。这次指南对应一次提交，留言会说明为什么改。

Push（推送）把你电脑上的提交传到 GitHub。

Pull（拉取）把 GitHub 上的新提交拿回你的电脑。

Pull Request / PR（拉取请求）不是直接把改动塞进 `main`，而是先开一张申请单，请别人 Review。现在的原型在 PR #6。

Review（评审）是对着这张申请单看：做的是不是这一阶段该做的，有没有把别的规则改坏。

Merge（合并）是评审通过、并且 Owner 同意之后，把分支上的改动收进 `main`。

Gate（阶段门）见第 1 节。一道门通过，只说明这一段的内容被接受。

Baseline（基线）是下一阶段可以依靠的那一版。它必须已经在 `main` 上。

Source of Truth（唯一可信来源）在这个项目里是 GitHub 上的仓库。聊天里说「通过了」，要以 GitHub 上 `main` 的内容为准。

Contract（契约）在这里不是法律合同。它是团队写下来的产品和设计规则，例如练习要短、答错后不能当场重答。

Contract Freeze（契约冻结）是以后某一天宣布：这些规则先定住，再按它们做正式版。现在还没有冻结。

Build（正式实现）是冻结之后，按契约把真正要发布的软件做出来。现在的原型不是 Build。

## 页面和程序

Prototype（产品原型）见第 1 节。

Human Review Surface（给人实际体验的表面）就是你现在打开的这些页面。评审的人不是只读文档，而是自己点。

HTML（网页的结构）决定这一页有标题、按钮和输入框。它像房子的墙和门。

CSS（样式）决定颜色、字号和间距。它像墙漆和家具摆法。纸色、墨色、那颗小星的大小，都在这里。

JavaScript（交互逻辑）决定按下「提交」之后发生什么：判对、判错、进入下一题。

Vanilla JavaScript（不靠大型框架的原生 JavaScript）就是这份原型的写法。没有 React、Vue 这种额外框架。

Frontend（前端）是人看得到、点得到的部分：页面、按钮、反馈。

Backend（后端）是藏在服务器上的部分，例如账号和云端数据库。这份原型没有后端。

API（应用程序接口）是程序和程序之间约定好的传话方式。这份原型没有自己的 API。

Runtime（运行环境）是程序真正跑起来的地方。现在是你电脑上的浏览器。以后的正式版，运行环境是微信小程序。

Local Storage（浏览器里的本地存储）可以在关掉页面后，仍把一些记录留在这台设备上。原型用它，是为了你能试「继续刚才的练习」。这是 Prototype-only implementation（只为原型准备的做法），不是正式小程序的存储设计。

State（状态）是「这一题现在处在哪一步」。这里主要有三种：ask（还没提交，可以改答案）、correct（已经判对，正在看「对」）、wrong（已经判错，正在看正确关系）。

Persistence（把状态留下来）就是刷新或下次打开时，还记得刚才那一步。已提交的对或错会留下，所以不能靠刷新把错题再答一次。

Refresh（刷新）是重新加载这一页。

Resume（恢复继续）是从首页点「继续刚才的练习」，回到刚才那一题或那个反馈。

Responsive（响应式）是同一份页面，在手机、平板、电脑上仍然是同一件事，只是字和键的大小会变。

Mobile-first（移动优先）是先把手机上的体验做顺。电脑也能用，但不是先为宽屏幕设计。

# 10. 这份原型用什么做的

当前页面是 HTML + CSS + Vanilla JavaScript。

选它，是因为：

- 文件少，打开就能看
- 改一句就能再体验
- 不需要安装大型框架
- 不需要打包
- 适合用来验证感觉，不适合被当成正式工程

正式微信小程序用什么技术，要等 Architecture（架构）阶段再决定。架构阶段负责「程序分成哪几块、数据放哪里」。那一阶段还没开始。

所以：现在浏览器里能跑，只说明原型能体验。它不代表正式产品也会是这一套网页技术。

# 11. 从这份网页到以后的小程序

```text
Product（产品：练什么、为什么练）
  ↓
UX（体验：先点哪里、答错后怎么办）
  ↓
UI（视觉：看起来像一张练习纸）
  ↓
Prototype（原型：现在这一步，真人来点）
  ↓
Architecture（架构：以后程序怎么搭）
  ↓
Mini Program Build（微信小程序正式实现）
```

# 12. 为什么会有好几条分支

这个仓库里，工作是一条条分开做的：

```text
main
 ├─ docs/ui-v01                      视觉规范，已经合并进 main
 ├─ docs/platform-mini-program-first 首发平台，已经合并进 main
 └─ prototype/v01                    现在这条：只做原型，还在 PR #6
```

每条分支只做一件事。这样：

- 视觉文档不会混进原型的试验代码
- Review 的人知道这一张申请单在看什么
- 做坏了可以不合并，`main` 仍然是上一版可信内容
- 以后查「当时为什么这样定」，有记录可看

有一条要记住：

Gate PASS（这一道门的内容通过了）还不等于它已经在 `main` 上。

顺序是：

```text
内容通过
  ↓
Owner 同意合并
  ↓
Merge 进 main
  ↓
这才成为新的 Baseline
```

聊天里说「看过了、方向对」，如果对应的 PR 还开着，下一阶段就不能把它当成已经生效的基线。

# 13. 给学生看的 5 分钟版

这是一个试验版网页，用来试试「短时间练数字关系」好不好用。它还不是完成品。

1. 打开之后，点「开始今天的练习」。
2. 看到题目，用数字键或键盘写出答案，再点「提交」。
3. 答错完全没关系。页面会给你看正确的关系。
4. 看一眼那句关系，再点「下一题」。
5. 做完或者做到一半都可以停。停了也不算失败。

如果你愿意说一句就好：哪里顺，哪里烦，答错之后还想不想继续。
