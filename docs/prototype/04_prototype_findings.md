# PT0 Prototype Findings

状态：供 Owner 与 ChatGPT 做 PT0 Gate Review。本文记录这次原型里实际看到的体验。它不改 Product、UX、UI 或 Delivery Platform 契约，也不冻结仍待确认的问题。

## 1. Scope

可点击的 Human Review Surface。技术是 HTML、CSS 和 Vanilla JavaScript。不是正式微信小程序工程，不是生产代码，不是架构基线。

样题、历史和熟练标记都是 Prototype Sample Data Only。原型题量不是正式 session 长度。

## 2. Test Environment

- 本地打开：`python3 -m http.server`，页面在 `prototype/`
- Chrome
- 375 × 812 手机竖屏
- 812 × 375 手机横屏
- 768 × 1024 平板
- 1280 × 800 电脑
- 没有学生参与。答错之后还愿不愿意继续，这次不能代替孩子做判断。

## 3. Flows Covered

首页三种状态、今日训练、平方专项、整数题、分数到小数、空提交、只按小数点、答对、答错、错题再出现、快完成了、先停一下、做完结束、先停结束、进度、打印预览、没有可印题目。

## 4. What Worked

- 首页只有一个填色主按钮「开始今天的练习」，里面带「大约 5～10 分钟」。专项和两个安静链接都更弱。
- 手机竖屏上，题目、答案框、56px 数字键和提交能同时留在一屏。整数题没有小数点。
- 题目在手机上是 40px，平板和电脑上是 64px。电脑上的点击键盘大约 48px，留在题目下面，没有盖过题目。
- 答对能看见勾和「对」，页面其余部分仍是纸色。
- 答错后键盘消失。原题变小。正确关系是 32px（手机），大于原题。有一句结构提示、空心圆和「看这里」，以及「下一题」。没有「你错了」，没有红屏。
- 空提交和只输入「.」会停在这一题，写「先写一个数。」，不计为做错。
- 分数题才有小数点，并且只能输入一次。
- 「先停一下」的确认是「先停在这里？已经做的会留下。」选择是「继续做」和「先停」。先停结束页没有星。
- 做完结束页的主按钮是「先到这里」。星大约 16px，只有一颗。
- 进度页是短列表，没有图表、百分比和连续天数。
- 打印预览只有题目。抽查的答案数字没有出现在预览里。
- 学生界面没有「浏览器」这几个字。本地记录写的是「当前设备」。

## 5. What Felt Wrong

没有发现需要立刻改契约的断点。下面几项是看了真实画面之后仍然不能代替人来拍板的地方，细节在后面各节。

- 暖纸色错误区在这台屏幕上能分出来，但是和底色很接近。
- 横屏要把数字键从 56px 收到 44px，题目和提交才能同时留下。
- 「再试一次」「你刚才写」和 400 / 550 / 700ms 都做成了可切换的原型，不应该在这次冻住。

## 6. First-use Findings

第一次打开，第一句是产品名，下面是一句说明，然后就是主按钮。不需要先看教程。下半屏留白很多，这和「一张安静的练习纸」一致，也不像作业系统的首页。

专项三个名字在按钮下面，找得到，尺寸明显更小。

本地记录那句在 375px 上会换行。语义仍然清楚。

## 7. Keypad Findings

手机竖屏：键高 56px，三列，0 在中间，整数题左边空着，不放灰键。题目在键盘上方，提交看得见。

电脑：物理数字键可以输入。点击键盘还在，但是只有大约 48px，靠左，题目仍是 64px。这一版里它没有抢过题目。是不是还嫌多，要在真的用键盘做完一组之后再看。

手机横屏见第 14 节。

## 8. Correct Feedback Findings

勾和「对」出现在答案旁边，不是全屏绿色。

原型默认停留 550ms。可以用地址参数换成 400 或 700：

- `?correctDelay=400`
- `?correctDelay=550`
- `?correctDelay=700`

700ms 这一档，单题做对后大约在 1 秒内进入结束页。系统减少动态时，等待收成大约 80ms，文字「对」仍然会先出现。

哪一档最自然，这次没有学生判断。不冻结。

Prototype Recommendation: 复核时先用 550ms。

Status: Owner / ChatGPT confirmation required

## 9. Incorrect Feedback Findings

默认不显示刚才写错的数字，只留下原题和正确关系。

`?wrongShow=B` 会在关系上面用弱于题目的字写「你刚才写：…」。不是红色。正确关系仍然更大。

两种都能走通。B 能让人看见自己写下的数，A 更安静。会不会帮助理解，还是多看一眼自己的错误，留给真人。

Notice-paper 是 `#F3EBE3`，底是 `#F6F3EC`。这块区域在当前屏幕上像一张稍暖的纸，不像报警。强光下还够不够显，仍是 UI Spec 里的 `PROTOTYPE_DECISION_REQUIRED`。这次不改颜色。

## 10. Revisit Findings

答错后，这道题会在后面两题之后再出现。若后面没有两题，就贴在队列末尾。同一题最多再排一次，避免停不下来。这是原型队列，不是正式抽题规则。

- `?revisit=A`：再出现时只显示域名，和普通题一样。
- `?revisit=B`：域名的位置改成「再试一次」，字号和颜色仍是标签，没有变红、没有叉。

B 在画面上不像惩罚标记。孩子会不会觉得被抓回来，这次看不出来。

Prototype Recommendation: 复核时两种都点一次。若有人觉得被追着罚，就拿掉这四个字。

Status: Owner / ChatGPT confirmation required

## 11. Session Completion Findings

临近结束时，标签位置变成「快完成了」。没有进度条，没有剩余题数。

做完以后，主按钮是离开。「再练一小段」是更轻的文字，放在进度链接下面。它目前会再开一段同样的原型队列。原型队列大约 10 题，所以「一小段」可能比字面感觉更长。这不代表正式产品的题量。

结束页有一点完成感，星很小，不像奖杯页，也不像分数海报。

「还剩多少」会不会让人焦虑，需要真人说。原型没有自行加上进度条。

## 12. Progress Findings

有样例时能看见日期、做完了或先停了、对了几题 / 做了几题，以及「正在熟悉」「再巩固一下」「有一些已经很稳」。

`?fresh=1` 时是「还没有练习」，主按钮回到开始。

「还没练到」按 UI Spec 通常不显示，所以主路径上没有这句话。分数专项的介绍句用的是 UX 里的「还没怎么练」。

这些熟练标记是写死的样例，不会因为刚才答对就真的变稳。

## 13. Print Findings

预览是白底黑字，有日期和「今天可以在纸上再写的题」。没有答案、没有「错题」、没有正确率。

`?printEmpty=1` 会说现在没有需要印的题，并给出「开始今天的练习」。

打印按钮调用当前环境的打印。做不到时显示「这个环境完不成打印。」

## 14. Responsive Findings

| 宽度 | 看到的 |
| --- | --- |
| 375 × 812 | 题目 40px。题目、答案、键盘、提交同屏。键 56px。 |
| 812 × 375 | 题目降到 32px，这一屏里读得清。数字键收到 44px，间距变紧，提交才没有掉出去。若维持 56px，键盘会盖住题目。 |
| 768 × 1024 | 题目 64px，仍是同一纵列。 |
| 1280 × 800 | 列宽 720px。题目 64px。点击键盘明显小于题目。不像后台。 |

横屏 32px 是否舒服，仍建议 Owner 拿手机横过来看一眼。44px 键只是这一版为了让题目和提交同时可见，不是改 UI Spec 的 56px 竖屏要求。

## 15. Accessibility Findings

- 对错都有文字：勾加「对」，空心圆加「看这里」，再加上正确关系。
- 声音关掉之后，这些文字还在。声音开关是「声音开 / 声音关」。
- 主按钮和竖屏数字键不小于规格。横屏短高度下数字键是 44px。
- 电脑上有焦点环。数字键、Backspace 和 Enter 接到了同一套输入。
- 减少动态后，答对不会停满 400–700ms。
- 这次没有做人读屏走查，也没有做 200% 缩放走查。

## 16. Mini Program Compatibility Observations

原型仍是网页，用来感受手机上的一页一题。

- 完成练习不依赖悬停、右键、多窗口或地址栏。
- 学生文案不写浏览器。
- 训练页没有底部导航。
- 进度、打印和专项用页内的「回到首页」离开。正式小程序可以换成系统返回，这里只是网页没有那条系统栏。
- 没有建立小程序工程，没有登录、云开发或后端。

## 17. Prototype Decisions

下面都是建议，不是冻结。

| 事项 | Prototype Recommendation | Status |
| --- | --- | --- |
| 答对停留 | 复核先用 550ms | Owner / ChatGPT confirmation required |
| 再出现时的「再试一次」 | 先保留成可切换项，两种都体验 | Owner / ChatGPT confirmation required |
| 是否显示刚才写的答案 | A / B 都留下，不默认冻 B | Owner / ChatGPT confirmation required |
| 横屏 32px | 这一屏可读；键为 44px 才能同时看见提交 | Owner / ChatGPT confirmation required |

## 18. Product Change Requests

无。

今日训练、三个域、本地、不登录，这些在原型里都还站得住。题量、5 分钟还是 10 分钟，继续保持未决。

## 19. UX Change Requests

无。

「再试一次」、剩余题数的不确定感、中断后首页是继续还是重来，都还要 Owner 自己点过，必要时再让一名目标年龄的学生点过。原型没有改 UX Spec。

## 20. UI Change Requests

无。

暖纸色、星、电脑键盘的强弱，都还在已通过的视觉方向里。横屏为了塞进一屏而把键收到 44px，是原型布局，不回写 UI Spec。

## 21. Prototype-only Fixes

- 横屏不再用固定键盘盖住题目。短高度下键为 44px，题目和提交同时可见。
- 空提交的「先写一个数。」不会留在随后的答对画面上。
- 键盘事件的目标不是按钮元素时，不再中断输入。

本地若写了 `localStorage`，只为了刷新后还能看到「继续刚才的练习」。Prototype-only implementation。不是存储架构。

小数「0.50」和「0.5」在原型里按数值比较，会算作同一个答案。这不是产品层的等价规则。

## 22. Remaining Open Questions

- 400 / 550 / 700ms 哪一档让人觉得「对」被看见了，又不会等。
- 「快完成了」够不够。
- 「再试一次」有没有负担。
- 横屏 32px 拿在手里是否还舒服。
- 暖纸色在亮处是否还看得出「看这里」。
- 电脑上的点击键盘会不会多余。
- 答错之后，学生还愿不愿意按「下一题」。这是这次原型最需要真人回答的一件事。

## 23. PT0 Gate Recommendation

原型已经能让人从首页走到做完、答错、再出现、先停、进度和打印。可以进入 PT0 Review。

不要把这次的样题、停留时间和「再试一次」写成冻结契约。请 Owner 先自己走一遍，并尽量让一名初中生答错一道之后继续下一题。
