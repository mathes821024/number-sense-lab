# Number Sense Lab 首次上线集中范围与七年级有理数设计

状态：`DESIGN — OWNER DIRECTION ACCEPTED, IMPLEMENTATION NOT STARTED`

日期：2026-10-12

上位设计：`docs/superpowers/specs/2026-10-12-knowledge-license-product-architecture-design.md`

## 1. 集中目标

首次上线前只集中完成四条主线：

1. 建立能回答“全不全”的知识全景与覆盖治理；
2. 为七年级孩子交付可实际训练的有理数计算闭环；
3. 微调现有前端，使科学感来自数学关系和工具，而不是换色或堆装饰；
4. 完成分层授权切换，并为 H5、微信、抖音、支付宝建立同一套发布 Gate。

上线前不增加账号、云同步、AI Tutor、教师端、内容管理后台或分析服务。这些能力保持未来私有/商业方向。

## 2. 三种不同的学习资产

现有 173 条内容主要属于有限的事实提取。后续内容不能全部硬塞进同一张静态关系表。

| 轨道 | 适合内容 | 持久身份 | 调度单位 |
| --- | --- | --- | --- |
| Fact Memory | 小九九、1～19 乘法、平方/立方/幂及反向映射、常见分数对应 | `relation_id` | 一条事实关系 |
| Calculation Skills | 有理数四则、约分、通分、开方、公式、估算检查 | `skill_id` + 可复现 `exercise_id` | 一个技能及其难度带 |
| Knowledge Atlas | 知识层级、前置、推导、表示转换、验证关系、未来主题 | `node_id` / `edge_id` | 不直接进入掌握调度 |

三条轨道可以互相引用，但不得混用掌握语义：看过地图不等于会算；算对一道随机题不等于记住一条事实；Atlas 节点也不自动进入每日训练。

## 3. Knowledge Atlas v0.1 的完整边界

Atlas v0.1 必须收录并标注状态：

- 10、20、100 以内凑整；
- 小九九与 1～19 乘法关系；
- 平方、立方、常见幂及反向映射；
- 分数、小数、百分数及循环小数；
- 开方、约分、通分；
- 完全平方、平方差、立方公式；
- 估算、区间、尾数、奇偶、因数结构；
- 七年级有理数：正负数、数轴、相反数、绝对值、比较、加减乘除、乘方与混合运算；
- 后续指数、对数、不等式、几何模型。

每个节点必须有：稳定 ID、名称、知识层级、学段、状态、前置、所属轨道和至少一个验收说明。状态只允许：

- `released`：已有正式可用体验；
- `contracted`：内容和交互契约已冻结，尚未发布；
- `mapped`：已进入完整地图，但不宣称已经可训练。

Atlas v0.1 的“完整”指上述主题都有位置、边界、依赖和状态；不指它们全部在首次上线时进入训练。

## 4. Fact Memory 首次上线范围

### 4.1 保留现有 173 条

现有 `relation_id`、答案和学习历史不得变化。新增内容只能追加，重叠事实优先复用旧 ID。

### 4.2 完整关系集合

- 小九九：无序乘法对 `1 ≤ a ≤ b ≤ 9`，共 45 条；
- 1～19 乘法：无序乘法对 `1 ≤ a ≤ b ≤ 19`，共 190 条，包含小九九；
- 凑整：分别对目标 10、20、100 收录 `1 ≤ a < target` 的缺数关系，共 `9 + 19 + 99 = 127` 条；
- 平方：`1²` 至 `100²` 与精确整数反向映射；
- 立方：`1³` 至 `20³` 与精确整数反向映射；
- 常见幂：以内容契约列出的基数/指数集合为准，正向与唯一反向映射成对；
- 分数/小数/百分数：完整地图覆盖常见分母；Mastery Core 只选择高复用、表述清楚的有限集合；
- 循环小数：保留现有循环节输入语义，扩展必须同时提供无括号读屏文本。

乘法的交换方向是同一条数学关系、同一份掌握证据；练习呈现可以稳定地产生 `a × b` 与 `b × a` 两种方向，但不能为交换顺序复制两个永久关系 ID。

### 4.3 每日训练不是全库随机

所有关系进入 Atlas/专项可见，不代表进入每日训练。关系清单增加 `collection`：

- `mastery_core`：可以进入每日训练；
- `reference_practice`：只在专项训练中主动选择；
- `exploration_only`：仅用于地图和解释，不进入掌握。

旧内容默认 `mastery_core`，避免历史行为变化。

## 5. 七年级有理数首发技能包

首发交付 8 个稳定 `skill_id`：

1. `g7-rational-sign-opposite-absolute`：正负数、相反数、绝对值；
2. `g7-rational-compare`：数轴位置与有理数比较；
3. `g7-integer-add-sub`：正负整数加减；
4. `g7-integer-mul-div`：正负整数乘除；
5. `g7-fraction-add-sub`：正负分数加减、通分；
6. `g7-fraction-mul-div`：正负分数乘除、约分；
7. `g7-rational-power`：负数底数、括号、乘方与绝对值；
8. `g7-rational-mixed`：含括号的有理数混合运算。

### 5.1 难度带

每个技能按 `foundation`、`standard`、`transfer` 三带生成：

- `foundation`：单一概念、数值小、一步或两步；
- `standard`：七年级课内典型结构，包含符号与必要化简；
- `transfer`：结构变式、估算检查或多表示，不引入未学代数规则。

首发默认只把 `foundation` 与 `standard` 放入日常技能训练；`transfer` 由学生主动进入。

### 5.2 精确计算

生成器和判题必须使用整数分子/分母的精确有理数模型，不使用浮点数决定对错。模型统一约定：

- 分母始终为正；
- 零统一保存为 `0/1`；
- 结果统一约到最简；
- 除数绝不为零；
- 中间值受安全整数边界约束；
- 同一 `seed + skill_id + band + index` 必须生成同一道题。

### 5.3 输入

新增两种输入能力：

- `signed_integer`：数字键盘增加正负切换；
- `signed_fraction_fields`：整体符号 + 分子框 + 分母框，不允许分母携带负号。

H5 物理键盘支持 `-`；四个小程序只靠屏幕键盘也必须完成作答。空输入、仅负号、分母为零均不记录为错误；等值但未约分的答案提示“化到最简”，不写入掌握证据。

## 6. 数学工具与解释模型

每道正式练习可提供三个并列工具，但允许某一题明确标记“不适用”：

| 工具 | 作用 | 示例 |
| --- | --- | --- |
| 直接算 | 最短、标准的计算过程 | 符号规则与逐步运算 |
| 结构算 | 利用关系、分解、数轴或公式 | `-7 + 12` 在数轴上右移 12 |
| 估算检查 | 判断符号、区间、数量级或尾数 | 结果应为正且小于 10 |

内容接口使用 `explanations.direct`、`explanations.structure`、`explanations.estimate`。原有 `hook`、`pattern`、`frames` 在兼容层映射到该接口，不改写旧内容。

答错和答对都可以主动打开工具。答对反馈默认短暂停留；点击“看原理”立即取消自动前进，打开三工具面板，学生点击“继续”后进入下一题。

## 7. 视觉微调

### 7.1 吉祥物

- 首页可保留一次欢迎姿态；
- 专项/知识地图最多作为边缘安静伙伴出现一次；
- 正确、错误和普通训练屏不再固定出现吉祥物；
- “太棒了”等固定幼儿式夸奖改为“正确”“关系成立”“检查通过”等中性反馈；
- 吉祥物状态不进入学习记录或业务判断。

### 7.2 科学感组件

首发实现四个跨端、无 SVG 依赖的共用组件：

- `RelationChain`：节点、关系线和方向；
- `NumberLine`：刻度、零点、当前位置和移动；
- `DecompositionSteps`：拆分与重组；
- `FormulaTransform`：等式逐步变形。

组件必须提供顺序化文本作为读屏退路；低动态模式直接显示最终状态；动画不参与判题。

### 7.3 知识地图

现有“知识地图”不再显示“敬请期待”，而是展示：

- 当前层级；
- 已发布、已契约、已映射三种状态；
- 前置与可迁移关系；
- 进入专项练习或查看解释的明确入口。

移动端显示分层列表与局部关系链，H5/PC 可以在同一数据上显示更宽的关系布局。不是两套地图。

## 8. 无障碍与真实设备

截图只能证明视觉层级，不能证明完整无障碍。首次上线 Gate 必须分别验证：

- H5 键盘焦点顺序、Enter/Backspace/负号、可见焦点；
- 读屏名称、状态与数学文本退路；
- 浏览器 200% 缩放和窄屏回流；
- `prefers-reduced-motion`；
- 微信、抖音、支付宝的安全区、底栏遮挡、触控目标和开发者工具/真机表现；
- 无图片、无音频、低动态时仍能完成同一学习路径。

未执行的平台只能标记“未验证”，不能写成“已支持”。

## 9. 分层授权切换

授权方案沿用上位设计：

- 软件代码与工程工具：MPL-2.0；
- 课程、教学表达、知识地图：All Rights Reserved；
- 品牌与视觉：All Rights Reserved + Brand Policy；
- 未来云端商业能力：私有仓库或商业许可证；
- 历史 MIT 权利保持不变。

授权切换是独立 PR，必须在内容与品牌继续扩展前完成或与它们同时进入同一明确切点。法律文本经专业律师复核后才可对外发布。

## 10. 四端上线定义

上线不是一句“能编译”，而是逐端状态：

1. `BUILD_VERIFIED`：本地可重复构建；
2. `TOOL_VERIFIED`：对应开发者工具打开并走完关键路径；
3. `DEVICE_ACCEPTED`：真实设备由 Owner/家庭完成体验验收；
4. `SUBMITTED`：已提交平台审核；
5. `PUBLIC`：平台审核通过并可访问。

H5、微信已有实施基线，但仍需按新版本重新过 Gate。抖音使用 Taro `tt` 平台插件，支付宝使用 `alipay` 平台插件；平台配置和能力实现只能进入 `app/platform/` 与平台配置文件。

外部平台审核、账号资质和发布时间由 Owner 决定。任何 AI 不得把 `BUILD_VERIFIED` 宣称为 `PUBLIC`。

## 11. 集中顺序

```text
授权切点设计 ───────────────┐
                            ├─→ Release Candidate
Atlas / 内容合同 → 七年级引擎 ┤
                            ├─→ H5/微信验收 → 抖音/支付宝验收 → Owner Release Gate
视觉组件与体验合同 ──────────┘
```

工程上先建立 Atlas、技能引擎和输入能力，再接内容与视觉；否则前端会围绕错误的数据模型返工。许可证切换可以并行准备，但独立 Review、独立合并。

## 12. 停止条件

除仓库既有停止条件外，出现以下情况也必须返回 ChatGPT/Owner：

- 新内容与现有 173 条产生语义重复但无法保留旧 ID；
- 七年级技能需要改写现有事实掌握语义；
- 某平台无法表达精确分数输入或读屏退路；
- 分层授权无法确定权利主体或文件边界；
- 发布动作需要尚未授权的账号、签名、审核承诺或付费。
