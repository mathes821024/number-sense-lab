# Number Sense Lab 知识、产品、授权与 AI 协作总设计

状态：`DESIGN — OWNER DIRECTION ACCEPTED, NOT CONTRACT FREEZE`

日期：2026-10-12

决策人：Owner

编排与 Gate Review：ChatGPT

## 1. 结论

Number Sense Lab 不应继续被定义成“若干典型算式的练习工具”，而应长期发展为一套跨年龄、跨知识层级、跨终端的计算认知基础设施：

1. 用 **Knowledge Atlas（知识全景图）** 表达“计算能力包含什么”；
2. 用 **Mastery Core（阶段掌握核心）** 表达“当前学习者必须练稳什么”；
3. 用 **Exploration & Transfer（探索与迁移）** 表达“如何从会算走向看见结构、选择策略和迁移”；
4. 用同一份平台无关的学习核心，同时服务 H5、微信小程序、抖音小程序和支付宝小程序；
5. 用“温暖的数学实验室”而不是“低龄儿童乐园”或“冷色科技面板”承载体验；
6. 从未来指定的切换提交开始，采用“软件代码 MPL-2.0 + 教学内容与品牌资产保留全部权利”的分层授权；
7. 采用“Owner 决策、ChatGPT 做重大设计与 Gate、Cursor/Grok Bot 承担低判断重复工作、专业角色按边界交付”的 AI 协作模式。

本文把上述方向收敛为设计基线。它**不修改当前 LICENSE，不改变业务代码，不代表 Contract Freeze，也不授权发布**。

## 2. 已验证事实、Owner 确认与待验证项

### 2.1 仓库事实

- 当前核心学习逻辑集中在 `src/core/`，平台能力通过 Adapter（适配层）隔离。
- 当前共用前端位于 `app/`，已有 H5 与微信平台实现。
- 当前正式内容已扩展为 8 个领域、173 条关系。
- 仓库现有架构契约已经明确：产品与学习契约属于核心，平台 API 属于适配层。

### 2.2 Owner 本轮确认

- 产品目标端是 H5、微信小程序、抖音小程序、支付宝小程序。
- H5 与微信小程序已经由 Grok Bot 跑通；本电脑有微信开发者工具，可继续做人类验收。
- 对知识全景、阶段掌握、探索迁移、视觉方向和分层授权的推荐方向予以接受。
- 低难度、低创造性、流程固定、频繁发生的工作，应优先交给 Cursor 或 Grok Bot。
- ChatGPT 的主要价值应集中在视觉方向、重大决策、跨角色一致性和 Review。

### 2.3 仍须以独立证据关闭的事项

- 抖音与支付宝的构建、开发者工具真机路径、平台审核差异尚未在本文中验收。
- H5 与微信“跑通”是当前实施基线；进入下一里程碑前仍需保留可重复的构建、自动检查和人类体验证据。
- 许可证切换的法定权利主体名称、历史贡献权利链和商标策略，必须在公开切换前完成法律复核。

## 3. 产品边界

### 3.1 北极星

帮助学习者形成可提取、可解释、可组合、可迁移的数与运算关系网络，使计算不只是“做对一道题”，而成为后续小学、初中、高中乃至大学数学的认知底座。

### 3.2 不是本项目的目标

- 不是把所有数学知识一次性塞进每日练习；
- 不是用题量、连胜、排行榜或强刺激替代掌握；
- 不是四个平台各自发展一套课程和判题逻辑；
- 不是因为“AI 教育”就立即加入聊天机器人、自动生成题或云端画像；
- 不是依靠一个吉祥物就宣称实现了拟人化；
- 不是试图通过许可证占有数学事实、方法或一般教育理念。

## 4. 知识与能力双层级

### 4.1 三个知识面

| 知识面 | 回答的问题 | 是否全部进入训练调度 |
| --- | --- | --- |
| Knowledge Atlas | 完整的计算知识、关系和依赖有哪些 | 否 |
| Mastery Core | 某阶段真正需要稳定提取的最小集合是什么 | 是，按阶段和目标选择 |
| Exploration & Transfer | 怎样解释结构、比较策略并迁移到新情境 | 否，按需要进入理解与探索路径 |

“内容完整”首先意味着 Atlas 有边界、有覆盖矩阵、有缺口记录；不意味着每条知识都变成高频闪卡。

### 4.2 知识层级

全景图至少能表达以下层次，并允许以后扩展，而不把它们混成一类关系：

1. 基础表征：数位、符号、量、分数与小数表示；
2. 基本事实：乘法事实、常见平方立方、常见分数小数百分数对应；
3. 关系族：倍半、补数、相邻关系、逆运算、等价变形；
4. 策略：拆分、凑整、补偿、分配、因数重组；
5. 公式与模式：公式不是孤立口诀，而是与可推导关系连接；
6. 估算与检验：数量级、合理性、逆向验证；
7. 迁移：新数、新表示、新情境中的结构复用。

### 4.3 能力层级

同一个知识项可以处在不同能力状态：

1. 见过；
2. 能计算；
3. 能直接提取；
4. 能逆向识别；
5. 能解释关系；
6. 能比较并选择策略；
7. 能迁移到新情境。

内容身份与能力状态必须分开。`relation_id` 是持久数据身份，不能因改文案、换主题、换平台或改变训练编排而随意变化。任何身份调整都必须有迁移方案并通过 `DATA_MIGRATION_RISK` Gate。

### 4.4 内容完备度治理

每一领域建立 Coverage Matrix（覆盖矩阵），至少记录：

- Atlas 范围与明确的非范围；
- 已实现关系、待设计关系、仅供探索的关系；
- 适用年龄/阶段与必要前置；
- 能力层级目标；
- 题型与反向变式覆盖；
- 讲解、例子、记忆钩子和验证方式；
- 内容来源、复核者、版本与稳定身份；
- 是否进入 Mastery Core 及其理由。

“典型算式摘录”可以作为种子内容，但不能再被等同于领域完成。领域完成必须由覆盖矩阵和 Review 证据证明。

## 5. 三条体验路径

### 5.1 Practice（练习）

- 目标：短时提取、稳定关系、形成日常节奏；
- 保持一题一屏、低干扰、可结束、不倒计时；
- 反馈只说明这次作答，不用羞辱、满屏红色或成瘾机制；
- 是主路径，但不是项目的全部。

### 5.2 Understand（理解）

- 目标：在需要时看见“为什么”和“还能怎样算”；
- 结构解释是可进入、可退出的，不强迫每题先上课；
- 使用数线、面积、分组、拆分、关系链等真正解释数学的表示；
- 记忆钩子服务于提取，不能替代数学关系本身。

### 5.3 Explore（探索）

- 目标：预测、比较、发现模式、验证猜想、迁移；
- 允许开放度高于日常练习，但不改变判题与掌握契约；
- H5/PC 可承载更丰富的关系可视化，小程序提供能完成核心探索的轻量版本；
- 平台能力不足时降低表现复杂度，不降低数学含义。

## 6. 视觉与拟人化方向

### 6.1 视觉北极星

**温暖的数学实验室**：可靠、清晰、有探索感，既不低幼，也不故作高科技。

科学感来自“观察—预测—推导—验证—建立联系”的行为和信息结构，不来自霓虹、深色驾驶舱、密集数据或装饰性公式。

### 6.2 年龄适配

- 面向低年龄时可以更亲近，但不使用幼儿园式奖章、撒糖和夸张庆祝；
- 面向初高中时，文字、留白、图形和角色语气应自然变得更克制；
- 主题可以替换颜色、背景、吉祥物、图标、装饰、动效和可选音效，但不能替换学习规则；
- 未来可有 `magic-academy`、`space`、`forest` 等主题，当前不因此承诺主题切换器。

### 6.3 拟人化不是吉祥物贴图

拟人化应主要来自稳定的陪伴行为：

- 知道什么时候鼓励、什么时候安静；
- 对错误表现出好奇和帮助，而不是评判；
- 能用一致语气提示下一步；
- 不挡题、不抢主按钮、不连续打断；
- 支持减少动态、静音、无动画退路；
- 吉祥物是可替换主题资产，不成为学习状态或业务逻辑的一部分。

### 6.4 当前 UI 的演进重点

- 保留已有的清晰卡片、安静练习流、进度与打印能力；
- 首页继续让“今日训练”成为唯一主行动；
- 专项训练页从“领域入口集合”逐步升级为能看见知识层级与成长位置的地图，但不做信息墙；
- 确认页提高任务含义和预期，而不是只留下大面积空白；
- 正确反馈减少过于低龄的固定赞美，按年龄与主题使用克制反馈；
- 错误反馈把已有的关系提示进一步连接到 Understand，而不是只在答错后临时出现；
- 移动端必须检查底部导航、安全区、字号和滚动，不让最后一组内容被遮挡。

## 7. 四端产品与技术边界

### 7.1 一套核心，四个交付面

```text
Knowledge / Curriculum
          ↓
Core Learning Engine
          ↓
Shared UI and Session Flow
          ↓
Platform Adapter
   ├─ H5 / PC Web
   ├─ WeChat Mini Program
   ├─ Douyin Mini Program
   └─ Alipay Mini Program
```

- `src/core/`：关系、判题、掌握、调度、学习者状态、迁移；不得调用平台 API。
- `src/adapter/`：平台无关的能力约定；不得包含 `window`、`wx`、`tt`、`my` 等实现。
- `app/`：共用页面、组件、主题与会话流程。
- `app/platform/`：存储、生命周期、安全区、导航、分享、导出、音频等平台实现的唯一归属。
- `h5/`：遗留/兼容浏览器资产按现有架构逐步治理，不发展成第二套学习产品。

### 7.2 交付顺序

1. H5 与微信：视为已形成实施基线，补齐可重复证据和人类体验验收；
2. 抖音：在不修改核心断言的前提下接入平台适配并做真机验收；
3. 支付宝：沿用同一方式接入并做真机验收；
4. 任一平台遇到限制时，先调整 Adapter 或呈现降级，不把平台限制上升为全产品规则。

“四端目标”不等于“四端必须同时发布”。每一端都必须独立通过构建、冒烟、关键学习路径和 Owner 体验 Gate。

## 8. 授权架构

### 8.1 基本原则

真正符合 Open Source（开源定义）的许可证不能禁止商业使用。若要保护项目的核心价值，不能写一个“禁止商用但仍称开源”的自定义许可证；应当把**可开源的软件**与**不开放复制许可的教学内容、品牌和视觉资产**分开。

版权保护具体表达，不垄断数学事实、一般算法、教学方法或理念。本项目的长期壁垒应来自高质量内容体系、验证数据、产品体验、品牌信任和持续迭代，而不是寄希望于一句许可证覆盖所有思想。

### 8.2 历史版本

- 已经按 MIT License 发布的提交和文件副本，继续受当时 MIT 授权约束，不能追溯撤回。
- 新授权只从 Owner 明确批准的 cutover commit（授权切换提交）开始适用于后续版本。
- 切换前必须确认仓库贡献者与资产来源，避免把无权重新授权的第三方材料纳入新声明。

### 8.3 切换后的默认分类

| 类别 | 典型路径 | 推荐授权 | 含义 |
| --- | --- | --- | --- |
| 软件与工程工具 | `src/`、`app/`、`h5/`、`config/`、`scripts/`、`test/`、构建配置 | MPL-2.0 | 修改过的 MPL 文件需按 MPL 提供源码；可与更大范围专有系统组合 |
| 教学与课程表达 | `content/`、`docs/curriculum/` 中的课程、题目编排、例题、讲解脚本、记忆钩子、知识图谱表达 | All Rights Reserved | 未经书面授权不得复制、改编、再发布或商用 |
| 产品与设计文档 | `docs/product/`、`docs/ux/`、`docs/ui/`、未明确开放的设计稿与研究资料 | All Rights Reserved | 公开可读不等于获准复制为另一产品 |
| 品牌与视觉资产 | `assets/brand/`、`assets/themes/`、`concept-design/`、`mockups/`、名称、Logo、吉祥物、主题图形 | All Rights Reserved + Brand Policy | 软件许可证不授予品牌、商标或视觉资产使用权 |

这里的 `scripts/` 指构建、检查和工程脚本，属于软件；“讲解脚本”指教学表达，属于受保护内容。最终边界由机器可读的文件清单与目录说明共同确定，不能只靠本表推断。

### 8.4 切换实施包

正式切换应作为独立法律/治理变更，不夹带产品功能，并至少包含：

- 根目录 MPL-2.0 `LICENSE`；
- `NOTICE.md`：说明分层授权、历史 MIT 边界和第三方材料；
- `CONTENT_LICENSE.md`：定义教学内容与文档的保留权利范围；
- `BRAND_POLICY.md`：名称、Logo、吉祥物、主题资产和兼容性描述的使用规则；
- `CONTRIBUTING.md`：贡献进入哪一类、采用什么 inbound license（入站许可）；
- 关键目录 README、文件头或 SPDX 标识；
- 一份由版本控制生成并 Review 的授权边界清单。

### 8.5 外部贡献

- 软件代码贡献默认以 MPL-2.0 入站，并使用明确的 Developer Certificate of Origin（开发者原创声明）或等效贡献流程；
- 在权利链和 Contributor License Agreement（贡献者许可协议）未定之前，不接收外部教学内容与品牌资产贡献；
- 任何未来需要双重授权或商业授权的模块，必须先设计足够的权利授予，不能事后要求贡献者补签；
- 未来云端账号、同步、教师端、机构服务或 AI 服务可以留在私有仓库或另行商业授权，不因客户端 MPL 自动开放。

### 8.6 法律 Gate

本文是产品与工程授权设计，不构成法律意见。公开切换前，Owner 必须让熟悉开源、著作权与商标的专业律师复核：权利主体、历史贡献、目录边界、品牌政策、隐私条款和目标发行地区。

## 9. AI 协作操作模型

### 9.1 角色边界

| 角色 | 主要负责 | 不负责 |
| --- | --- | --- |
| Owner | 目标、优先级、人类体验、重大取舍、合并与发布 | 把最终判断交给 AI 自动完成 |
| ChatGPT | 重大产品/视觉/架构判断，跨角色编排，Contract Gate，Milestone Review | 长期占用时间做可机械重复的批量实施 |
| Cursor | 契约与文档工作台、固定格式维护、PR 创建与维护、按清单做专业 Review | 未经 Gate 重定义产品、课程或体验 |
| Kimi | 课程体系、内容覆盖、例题、讲解、记忆钩子、教学顺序 | 独立修改产品、视觉或运行时契约 |
| Doubao | 视觉资产工程、图标、吉祥物、主题包；支持抖音端视觉交付 | 决定判题、掌握、调度和内容身份 |
| Grok Bot | 冻结后集中实现、测试、重构、分支与提交、建议 PR 文案 | 把实现便利悄悄变成新产品规则 |
| WorkBuddy | H5/微信平台接入、开发者工具、构建、发布与平台验证 | 拥有第二套学习核心或修改上游契约 |

支付宝端交付沿用同一平台适配原则；具体执行者在该里程碑开始前由 Owner 指定，不能因角色未定而把支付宝逻辑写进核心。

### 9.2 按判断强度分流

| 任务特征 | 默认承接者 | Gate |
| --- | --- | --- |
| 高创造性、高不可逆性、改变产品含义 | ChatGPT 组织专业角色提出方案 | Owner 决策 |
| 视觉北极星、整页体验、重大交互 | ChatGPT 定方向，Doubao 出资产方案 | Visual Asset Gate + Owner 体验 |
| 课程结构与内容完整性 | Kimi 设计，Cursor 整理契约 | ChatGPT Curriculum/Contract Review |
| 低难度、低创造性、流程固定、频繁 | Cursor（文档/PR）或 Grok Bot（代码/测试） | 自动检查 + 抽样 Review |
| 冻结后的集中工程实现 | Grok Bot | ChatGPT Milestone Review |
| 平台构建、工具链、发布适配 | WorkBuddy / 对应平台支持角色 | 平台冒烟 + Owner 真机验收 |

### 9.3 何时必须返回上游

执行智能体不因“小问题”频繁停顿，但出现以下情况必须报告，不得自行改义：

- `CONTRACT_CONFLICT`
- `DATA_MIGRATION_RISK`
- `CONTENT_ID_CONFLICT`
- 无法保持向后兼容
- 安全、隐私、授权或不可逆数据风险
- 实现证据表明已冻结假设不成立

- 冻结 Atlas、Mastery Core、Exploration 的数据边界；
- 冻结知识层级、能力层级和持久 ID 规则；
- 先选择一个领域做完整样板，再批量扩展。

### M3：体验与视觉样板

- 以一组完整手机页面和一组 H5/PC 页面展示三条体验路径；
- Doubao 完成 CSS/图片/吉祥物/图标/装饰/主题 manifest 分解；
- ChatGPT 运行 Visual Asset Gate 与 Contract Gate；
- Owner 与家庭成员在真实设备上体验。

### M4：集中实现

- Grok Bot 按冻结契约实施，不边做边重定义；
- 先完成一个知识领域的纵向闭环；
- 通过后再用相同模式扩展其他领域；
- Cursor 维护 PR 和契约一致性。

### M5：四端交付

- H5、微信先完成回归和人类验收；
- 抖音、支付宝依次完成 Adapter、构建、冒烟、真机与发布 Gate；
- 每一端可以独立决定发布时间，但不得分叉学习含义。

## 11. 验收框架

### 11.1 内容

- Coverage Matrix 能解释“完整到哪里”和“为什么进入/不进入掌握核心”；
- 正向、逆向、变式和解释不再只覆盖典型算式；
- 每个新增关系有稳定 ID、来源、复核和迁移判断；
- 内容专家检查数学正确性，真实学生检查能否理解。

### 11.2 学习

- 同一答案在四端得到同一判定与掌握变化；
- Practice、Understand、Explore 的边界可辨认且可互相进入；
- 解释不干扰短练习，探索不污染掌握统计；
- 不因动画、音效或角色资产缺失而无法完成训练。

### 11.3 视觉与可用性

- 手机、平板、桌面关键视口无内容被安全区或底栏遮挡；
- 数学内容在所有平台保持清晰、可读、可触控；
- 对错不只靠颜色，焦点、键盘、减少动态和静音有退路；
- 低龄亲和与青少年克制可以由主题和语气适配，而不改变核心。

### 11.4 工程与平台

- 现有核心自动测试保持通过，新增契约有对应测试；
- 平台 API 不进入 `src/core/` 或共用组件；
- H5、微信、抖音、支付宝分别有可重复构建与冒烟记录；
- 学习者历史迁移通过固定 fixtures（测试夹具）验证；
- 每一里程碑保留回滚点，平台适配失败不伤及核心与数据。

### 11.5 授权

- 每个发布文件能确定属于 MPL、保留权利或第三方许可；
- 软件包不意外携带受保护的课程/品牌源资产；
- 分发物保留 MPL、NOTICE、第三方归属和源码提供义务；
- README 不使用“全部 MIT”“全部开源”等与分层授权冲突的表述。

## 12. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 追求知识完整导致范围爆炸 | Atlas 完整、Mastery Core 克制；一次只做一个领域样板 |
| 层级很多但学生看不懂 | 内部模型可以精细，界面只展示当前有用的一层 |
| 视觉升级悄悄改变学习机制 | 视觉稿先过 Gate；判题、掌握、调度和错题语义保持冻结 |
| 四端适配演化为四套产品 | 核心、状态和共用 UI 单一来源；差异只进 Adapter |
| 吉祥物造成低幼感 | 降低出现频率，年龄化语气，允许主题替换与静默退路 |
| 分层授权边界模糊 | 目录说明 + 文件标识 + 机器清单 + 法律复核 |
| 历史 MIT 已允许复制 | 承认不可撤回；用后续内容、品牌、服务和持续演进建立优势 |
| AI 协作角色多、协调成本高 | 按判断强度分流；冻结后集中 Build；只在真实冲突时返回上游 |

## 13. 本设计冻结什么、不冻结什么

### 13.1 本轮方向已确认

- 三层知识架构与知识/能力双层级；
- Practice / Understand / Explore 三条体验路径；
- “温暖的数学实验室”视觉北极星；
- H5、微信、抖音、支付宝的一核四端方向；
- MPL-2.0 软件 + 受保护教学内容/品牌的分层授权方向；
- ChatGPT 高判断、Cursor/Grok 低判断重复工作的协作原则。

### 13.2 必须另行冻结

- 每个领域的完整 Coverage Matrix 与 Mastery Core 清单；
- 新知识模型字段、关系类型、能力状态和迁移合同；
- 新整页视觉稿与组件契约；
- 授权切换提交、法定权利主体和最终法律文本；
- 抖音、支付宝的实施里程碑、执行人和发布顺序；
- 任何云端、账号、同步、教师端或 AI 能力。
