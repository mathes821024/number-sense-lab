# 跨端框架

状态：A1 方向已接受，按复检意见修订。Taro 4 + React 是 H5 + 微信垂直切片的已选技术假设，不是已经证明的四端最终框架。Owner 尚未冻结。本文不改 `LICENSE`，不改学习契约，也不开始迁移。

## 背景

产品要同时到达 H5 / PC、微信小程序、抖音小程序、支付宝小程序。Owner 不要四套前端。

已经成立的事实：

- `src/core/` 是普通 JavaScript 模块，并且有测试禁止它碰平台 API。
- 存储已经有一个浏览器适配文件。
- 界面在 `h5/`，用 DOM，不是 React，也不是 Vue。
- 主题槽位和能力档位已经分开。
- v0.1 的交付说明把微信写成首发实现、把 H5 写成后续兼容面。实际可运行的 V0.3 是 H5。下一阶段要同时证明 H5 和微信，而不是再维护两套页面。

本文不改写那份旧交付说明的产品含义。它只决定下一次客户端工程怎么摆。

## 决定要满足的事

- 核心继续平台无关，现有学习测试不用为了换框架改断言。
- 四个端共用页面组件和 `math-lab` 槽位。
- 平台实现只放在 `app/platform/`。`src/adapter/` 只留存储约定。
- 一个人加 AI 团队能看懂构建。
- 先做 H5 + 微信的四屏切片，失败时可以停，不伤核心。

## 候选

只比和这个仓库有关的两条路。

| | Taro 4 + React | uni-app + Vue 3 |
| --- | --- | --- |
| 四端 | 官方插件包含 H5、微信、抖音（头条）、支付宝 | 同样覆盖这四端，条件编译处理差异 |
| 和现有核心 | 核心保持 ESM，由页面调用 | 同样可以调用 ESM 核心 |
| 和现有界面 | `h5/app.js` 都要重写 | 同样要重写 |
| 组件语言 | 仓库里没有 React。Taro 这条线以 React 最完整 | 仓库里没有 Vue。uni-app 以 Vue 为先 |
| 平台差异写在哪 | 独立文件和 `TARO_ENV`，适合薄适配层 | 模板里的条件编译，容易写进组件 |
| 测试 | 核心仍用 `node --test`。组件测试另加 | 同左 |
| 构建 | 多一套 Taro 编译 | 多一套 uni 编译 |
| 谁来做 | Grok Bot 写共用组件；WorkBuddy 跑微信工具；豆包跑抖音 | 分工相同，但条件编译更难评审 |

两条都能到达四端。差别在差异会不会漏进组件。

不另找第三套框架。再引入一个「只擅长 H5」或「只擅长某一个小程序」的框架，会回到四套界面。

## 建议

**Taro 4 + React 是第一跨端垂直切片的已选技术假设。**

它用来验证同一份页面能否在 H5 和微信里走完首页、训练、答对、答错，并调用同一个核心。四端都在 Taro 的平台插件里，所以这条假设值得拿来试；切片跑通之前，不把它写成已经证明的长期最终框架。跑通之后，才从架构假设升为实施基线。抖音和支付宝仍要等这次证据，不在这一刀里开工。

选它来试的原因：

- 四个目标端都在 Taro 4 的平台插件里，不需要为抖音或支付宝换一套工程。
- 核心不用改写成某个框架的响应式对象。页面拿核心的纯函数结果来渲染。
- 平台文件可以和组件分开，评审时看得到哪一行是微信才有的。
- 仓库还没有任何 UI 框架。选 Taro 时用它最完整的 React，而不是为了 uni-app 再学一套 Vue。
- 现有 H5 可以留到切片对齐，失败就删掉新目录。

不选 Vue 作为第一写法，是因为当前代码没有 Vue，而 uni-app 的便利主要来自 Vue。若这条切片假设失败，uni-app + Vue 3 是保留的下一家，不是平行开工的第二套，现在也不实现它。

## 不选的路

- 四个原生小程序加一个 H5：四次改需求。
- 把 `h5/app.js` 当成长期共用层：小程序没有这套 DOM。
- 现在就重写全部 V0.3 页面，并同时开四个端。
- 按流行度选择。流行只说明招人方便，不能代替上面的适配边界。

## 现有 H5

切片期间它是行为参照。对齐之后，Taro 编出的 H5 成为浏览器壳，`h5/app.js` 退出主路径。不是永远保留，也不是框架一选定就删掉。

## 预计能共用多少

这些是范围，不是测量值。

| 类别 | 预计 | 置信度 |
| --- | --- | --- |
| `src/core/` 与现有学习测试 | 基本原样留下 | 高 |
| `content/` | 原样留下 | 高 |
| 主题槽位和令牌 | 共用，图片格式按端退回 PNG | 中 |
| 四屏的界面结构 | 一套组件编到 H5 和微信 | 中 |

## 平台差异放哪

平台实现只在 `app/platform/`。`src/adapter/` 只保留存储约定，不放各端实现。细节见 `docs/architecture/02_cross_platform_frontend_architecture.md`。

`app/platform/` 负责：存储实现、音频、安全区、生命周期，以及以后的分享和导出。登录和支付不在这一轮。

答对后的短暂停顿留在共用界面。不为四个端各写一个计时适配器。生命周期信号可以取消还没走完的反馈。

屏幕键盘、题目、反馈文案、底部入口的显隐，放在共用组件。

## 第一刀怎么证明

同一份 Taro 页面，在 H5 和微信开发者工具里走完：

- 首页进入训练
- 答对后短暂停顿进入下一题
- 答错后看见正确关系，按「下一题」，不能当场重做

同时 `npm test` 里现有的判断、掌握和调度断言不变。

做不到这一点，就不加抖音和支付宝，也不删 `h5/`。

## 迁移

不整体翻写。顺序见 `docs/architecture/02_cross_platform_frontend_architecture.md`。

风险：SVG 和 WebP 在某一端不合格；Taro 编译比现在的无打包 H5 重；React 对只写过 `h5/app.js` 的路径是新表面。缓解：PNG 已经在资产包里；切片只含四屏；核心测试独立于 Taro。

可逆：新目录失败就停。核心和当前 H5 仍能运行。
