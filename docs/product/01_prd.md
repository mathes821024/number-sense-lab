# Number Sense Lab｜数感训练场

# Product Requirements v0.1

状态：P0 产品建议，供 Owner 与 ChatGPT 做 Product Gate Review。

本文不是 Contract Freeze，也不代表 Owner 已经拍板。文中的「产品建议」是 Product Manager 的提案；「待验证问题」留给后续 Gate，不在本轮自行冻住。

# 1. Executive Summary

Number Sense Lab 是一个轻量、开源的数感训练工具。v0.1 只服务初中阶段、计算还不够顺的学生。它不提供大题库，也不把现成数表搬到网页上。

学生每天用 5～10 分钟，对一小批高频数字关系做短时、可反馈、可重复的提取练习，把「现场算一遍」逐渐变成「直接想起来」。

v0.1 只验证三个训练域：平方、常用乘积、分数到小数。一次训练必须能在手机或电脑上独立完成，不登录、不依赖后端。系统记录正确率、反应时间和错题，并让尚未稳定的关系在以后的训练里再次出现。

产品是否有用，不看刷了多少题，而看两件事是否同时发生：学生愿意自己再打开；同一批关系变得更准、更稳。反应时间只在可比的作答里作为辅助观察，不能把换了输入方式造成的变慢解释成退步。

# 2. Problem

初中数学里，大量新知识压在少数旧关系上面：平方、常见乘积、分数和小数的对应。基础一般的学生并不是「完全不会」，而是这些关系还停在现场计算。一慢，后面的步骤就容易断，也更容易出现低级错误。

现有练习方式帮不到这个具体问题：

- 口算和题库应用靠不断出新题来制造练习量。学生做完一套，下一套又是新的，看不出某一个关系有没有真的变成提取。
- 整页数表适合查阅和抄写，不适合判断「不看表时还能不能想起来」。把表放在屏幕上，练的是查找，不是提取。
- 只记对错、不看稳定性和反应时间，会把「慢慢算对了」当成「已经会了」。
- 只追求速度，又会把焦虑和机械背诵当成数感。

Owner 首先要解决的，是自己孩子的日常：放学后没有老师陪着，仍然能做一小段有终点的练习，并且过几天能看出那些容易错的关系有没有变稳。

# 3. Target Users

v0.1 只定义一种使用者：正在练的学生。不设老师端，不设家长端。

**主要用户**

- 初中生。
- 尤其是基础一般或中等、计算偏慢、同一类小错会反复出现的学生。
- 第一个真实用户是 Owner 的孩子。v0.1 的价值验证以这一个学习者的连续使用为准，不假设已经有班级或一批用户。

**使用情境**

- 每天一段，落在 5～10 分钟里。
- 家里自己练，不依赖老师在旁边判题。
- 手机、平板、PC 都可能是当天的那一台设备。

**不是 v0.1 的用户**

- 需要班级管理的老师。
- 需要远程看报表的家长。家长如果在场，看的是孩子同一台设备上的练习，而不是单独的后台。
- 小学高年级、高中基础计算、成人脑力训练。这些是以后的可能扩展，不进入本版内容。

# 4. User Needs

学生需要：

- 打开就能开始，不用注册。
- 清楚知道这一小段什么时候结束。
- 做完立刻知道对错；错了能看见正确关系，而不是只看见一个叉。
- 已经稳定的关系少再出现，还不稳定的关系会再遇到。
- 感到「今天练完了」，而不是「题永远做不完」。
- 不被倒计时、排名或失败动画推着跑。

Owner 需要：

- 一个小到能做完的首版，用来判断孩子是否愿意再练，以及同一批关系是否变准、变稳。
- 屏幕练习和纸笔练习是同一批关系，而不是两套无关材料。

# 5. Product Value Proposition

相对普通口算应用和题库，Number Sense Lab 的价值是：

- **关系集合是有限的。** 练的是一批会被反复用到的数字关系，不是无限新题。
- **目标是提取，不是做完。** 进度看一个关系有没有变稳，不看章节完成百分比。
- **正确、稳定、速度是三件分开的事。** 算对但很慢，不等于已经能提取。
- **错了还会再见到。** 练习会回到尚未稳定的关系上。
- **纸和屏幕连着。** A4 打印的是当前要复习的关系，用来离开屏幕继续提取，不是装饰海报。

一句话：用很短的每天练习，让少数高频关系变得又准又稳，并且越来越不用现场算。

# 6. Core Learning / Training Hypothesis

如果学生在数天里反复提取同一批高频关系，并在答错后看到这个关系本身、而不是再被塞进一套新题，那么这些关系会从现场计算转为提取。

可观察的结果：

- 同一关系的正确率上升。
- 在同一种输入方式下，同一关系的反应时间中位数下降。跨输入方式的时间差不单独当成退步或进步。
- 同一个错误更少复发。
- 一个关系能在另一天仍然答对，而不只是当天连对。一次正确但慢，不把已经稳定的关系打回动摇。

这个假设不声称学生的数学成绩会立刻上升。v0.1 要验证的是提取是否发生、学生是否愿意继续练。与校内大题的迁移，只做很轻的连接，不在本版证明。

# 7. Core Scenarios

**场景 A：今天练一段**

学生放学后打开手机，进入今日训练。系统从三个域里抽出尚未稳定的关系。学生逐题输入，立刻得到反馈。到达本节的结束条件后，看到今天练完了，以及哪些关系比昨天更稳。没有做完的新题不会被说成失败。

**场景 B：只补一块**

学生知道平方容易错，主动进入平方专项。本节只出这个域。结束条件和反馈与今日训练相同。

**场景 C：错了还会再见**

学生答错一个关系。本节稍后再次出现它，而不是紧接着连打很多遍。下一次今日训练仍会优先遇到它，直到它变稳。

**场景 D：纸上再提取一次**

周末或写作业前，学生生成并预览当前还不稳定的关系。纸上只有题目。当前客户端若能打印、分享或保存，学生可以离开屏幕再提取一次；做不到时会说明。下一次打开应用，这些关系仍然会被问到。这份纸页不替代判题和记录。

**场景 E：换到电脑**

学生在 PC 上用键盘输入，完成同一种训练。熟练度记录在这一台设备上。换设备不在 v0.1 里同步。

# 8. User Stories

- 作为一个初中生，我希望打开就能开始今天的一小段练习，这样我不用准备账号，也不会面对做不完的题海。
- 作为一个初中生，我希望答错时看到正确关系，这样我知道错在哪里，而不是只被判定失败。
- 作为一个初中生，我希望已经会的少再出现、还不稳定的会再出现，这样我的时间花在还需要提取的关系上。
- 作为一个初中生，我希望今天有一个明确的结束，这样我可以停下来，而不是被催着继续。
- 作为一个初中生，我希望在手机和电脑上都能把同一段训练做完，这样当天用哪台设备都可以练。
- 作为一个初中生，我希望能把还不稳定的关系印到纸上再写一遍，这样屏幕练习和作业里的纸笔是同一批关系。
- 作为 Owner，我希望连续几天后能看出孩子是否自己还愿意打开，以及同一批关系是否更准、更稳，这样我能判断 v0.1 值不值得继续。

# 9. MVP Scope

v0.1 只验证三件事：学生是否愿意每天练一段；这一小段能否独立做完；三个域里的关系是否出现正确率、稳定性和反应时间上的变化。

**三个训练域**

1. 平方。
2. 常用乘积。
3. 分数到小数。

**学生能完成的事**

- 开始今日训练，或进入其中一个专项。
- 用确定性方式输入答案并立刻得到判题。
- 答错后看到正确关系。
- 在本节结束时看到以正确和稳定为主的结果。
- 查看很简单的近期记录：最近几次练了没有、正确率、哪些关系还不稳定。
- 生成并预览当前不稳定关系的 A4 题目页。打印、分享或保存由当前客户端适配。
- 在手机、平板和电脑上完成上述流程。v0.1 首发是微信小程序；H5 / PC 是同一产品的一等客户端方向。不要求四个客户端在 v0.1 一起发布。

**系统要留下的事**

- 每次作答的对错、反应时间，以及当时的输入方式。
- 错题。
- 每个关系的熟练状态。
- 尚未稳定的关系如何进入以后的训练。

这些记录留在本机即可。v0.1 不需要账号，也不需要服务器，就可以完成核心价值验证。

**内容边界**

每个域都是一个小而有限的精选关系集合，用来在大约两周的每天练习里被重复遇到。v0.1 每个域不超过 40 个关系。这个上限是内容契约：候选范围不是自动生成的全集。本轮不列出完整题目。具体选哪些关系，留给后续 Content Contract。

- **平方：** 默认关系是 6² 到 20²，外加 25²，只问「这个数的平方是多少」。这个默认范围本身不超过 40。1² 到 5² 不进入默认队列。开方、更高次方不在本版。25² 进入默认范围已经 Content Review 正式批准（CONTRACT ALIGNMENT，2026-09-29），这不是范围扩张，而是与已冻结课程内容的对齐。平方的完整知识地图（1²–100²）作为内容资产存在于 Content Contract 中，但只有默认关系进入训练、掌握度与抽题。默认范围在第一个学生身上是否合适，仍是待验证问题。
- **常用乘积：** 不是 6 到 19 的完整笛卡尔积，也不是完整乘法表。6 到 19 只是候选范围。v0.1 从中精选不超过 40 个高价值关系，只问两个数的积。交换因数不另算成第二条关系。选择时看它在初中运算里是否较高频，是否有数感或速算上的结构价值，是否会在后来的代数、几何或计算里重复出现并造成负担，并且不与平方域重复。不按任何现成数表的分族方式组织。
- **分数到小数：** 分母 2、4、5、8、10、20、25 只是候选池，不表示这些分母下的全部分数都会入选。最终仍是有限精选，不超过 40 个关系。方向只做分数 → 小数。循环小数不在本版。

具体题目清单不在本 PRD 中生成，也不从任何现成数表抄录名称、分类、版式或原表。

# 10. Out of Scope

v0.1 不做：

- 登录、云账号、多设备同步。
- 班级、排行榜、社交、分享成绩。
- 支付。
- AI 老师、大模型对话、自动出讲解长文。
- OCR、手写识别、语音输入。
- 完整初中数学课程、完整计算题库、应用题引擎。
- 老师后台、家长后台、多租户、复杂后端。
- 立方、整数次方、相邻整数的和与积、补数、半值与倍值等其他方向。
- 小数 → 分数。它被一个尚未决定的答案规则挡住，见待验证问题。
- 开方、逆问「哪个数的平方是这个数」。
- 循环小数，包括以 3 为分母的关系。
- 可消费的金币、商店、惩罚、生命值。
- 倒计时、限时失败、向学生展示毫秒或秒数。
- 把数表贴在答题界面里供对照。

没有看到必须打破这份清单才能验证核心价值的理由。

# 11. Training Loop

v0.1 的主循环是：

选择训练 → 出题 → 输入答案 → 判题 → 即时反馈 → 记录表现 → 调整后续出题 → 继续，直到本节结束 → 完成本次 session。

**进入**

- 今日训练：三个域里尚未稳定的关系混合出现，优先最近错过的、状态动摇的、以及还没在另一天被确认过的。一次正确但明显偏慢，可以提高以后抽到它的优先级；这一次慢，不把已经稳定的关系降成动摇。
- 专项训练：只出选定的一个域，优先级规则相同。

**一题**

- 一次只呈现一个关系，不附带对照表。
- 学生提交前可以改答案。提交后才判题。
- 从题目出现到提交的时间被记录，同时记下这次使用的输入方式。学生看不到计时。
- 这个时间用来观察同一个学生的趋势。它不是单独成绩。手机点按和物理键盘的时间差，不能直接解释成数学能力变化。v0.1 不做复杂的跨方式校准。

**反馈**

- 答对：短、轻、明确，然后进入下一题。
- 答错：显示正确关系，并给一句结构性提示，例如这个平方就是这个数乘自己，或这个分数为什么写成这个小数。不羞辱，不播放强烈失败效果。

**错题如何再出现**

- 同一节里：错过的关系在隔开若干题之后再出现，不紧挨着连做，同一节里也不反复磨同一题。
- 以后的节：它保持「未稳定」，并在今日训练和对应专项里优先出现。
- 隔开几题、同一节最多再出现几次，是待验证问题。原则先定：要再出现，但不在一节里惩罚式重刷。

**本节何时结束**

- 本节必须有终点，并且应当能落在 5～10 分钟里。
- 学生可以提前停止。已经做完的作答要保存。提前停止记为未完成 session，不记为失败。
- 用题量结束还是用时长结束，以及具体数字，是待验证问题。产品要求只有一条：终点可见，并且完整做完时应当落在这个时间窗里。

**结束后**

- 先呈现正确率，以及哪些关系比上次更接近稳定。
- 不呈现排名，不呈现原始反应时间。
- 学生可以就此结束。不默认自动进入下一节。

# 12. Content Model

内容模型是原创的，只借用数学事实本身。不使用现成作品的名称、分族、版式、表述和原题表。

一个**关系**是学生最终应当直接想起来的一条数字事实。它包含：

- 问法。
- 可接受的答案。
- 所属的域。
- 只在答错后出现的一句结构提示。

v0.1 的问法以直接提取为主。每个域可以有少量一步应用，用来把关系和初中数学里真正会遇见的用法连上，例如「边长 15 的正方形，面积是多少」。一步应用仍然只使用已经纳入该域的那条事实，不引入新知识点、图形题或文字应用题。一步应用在每个域里是少数，不能把本节变成综合练习。

**熟练状态**只使用四个，供学生和后续设计理解：

| 状态 | 含义 |
| --- | --- |
| 未练 | 还没有答过 |
| 学习中 | 答过，但还不能算稳定 |
| 稳定 | 满足下面的稳定原则 |
| 动摇 | 曾经稳定，之后再次答错，或多次表现持续异常。一次正确但慢，不能单独造成这次降级 |

**稳定原则**

答对一次不是掌握。一个关系要同时满足：

- 多次答对，而不是一次。
- 这些答对不全在同一天。
- 最近的作答里没有错过。
- 答对但慢，只计入正确率，不单独把这个关系推进到稳定。慢的判断用这个学生自己、同一种输入方式下的作答，不用全班统一的秒数门槛，也不把另一种输入方式的时间直接拿来比。

具体次数、跨几天、多慢叫做「慢」、连续几次才算异常，留给后续 Technical / Evaluation Design，不在本 PRD 冻住。产品要求是上面的原则。建议的起点只用于「进入稳定」：至少 3 次答对，其中至少 1 次在另一天，且最近 2 次没有错过。这只是起点，不是冻住的算法。

正确但慢：仍然算正确，不算失败，可以不推进到稳定，也可以影响后续抽题优先级。反应时间是辅助证据，不是单次状态降级触发器。已经稳定的关系，不能因为一次偏慢就变成动摇。它进入动摇，至少要再次答错，或多次表现持续异常。一次走神、一次换到更慢的输入方式、一次点错后删掉重输，都不够。

# 13. Functional Requirements

以下都是 v0.1 的产品要求。优先级只有「要有」。没写在这里的，默认不做。

1. 学生可以在不登录的情况下开始今日训练或一个专项。
2. 今日训练和专项走同一个作答、判题、记录和结束规则。
3. 一次只出一道题，答题时不提供对照表。
4. 手机和平板上用屏幕数字键盘输入。PC 上物理键盘和点击输入都可以完成提交。
5. 小数答案可以输入小数点。分数题不在 v0.1 的输入范围里；本版只让学生输入小数。
6. 提交后立即判对错。
7. 答错时给出正确关系，以及一句结构提示。
8. 每次作答保存对错、反应时间，以及输入方式。输入方式至少区分物理键盘和屏幕数字键盘。不采集设备型号。
9. 错过的关系会按第 11 节的原则再次出现。
10. 每个关系有且只有未练、学习中、稳定、动摇四种状态之一。
11. 学生可以提前结束，已做作答仍然保存。
12. 本节结束时，学生能看到正确率，以及关系是否比自己上次更接近稳定。
13. 学生能看到最近几次 session 的日期、是否做完、正确率，以及当前还不稳定的关系。不提供图表墙和排名。
14. 学生能生成并预览当前不稳定关系的 A4 题目页。答案不出现在同一眼能看见的位置。打印、分享或保存由当前客户端适配；做不到时说明，不改变题目内容。
15. 同一台设备、当前客户端上的进度在下次打开时还在。清除该客户端的本地数据会丢失进度；v0.1 接受这个限制，并用简单文字让学生知道进度只在这台设备上，不会自动同步。
16. 反馈可以有轻量的完成标记、轻动画和可关闭的轻音效。音效关闭后，训练仍然完整。
17. 任何完成训练所必需的操作，都不能只依赖悬停、右键或桌面快捷键。

# 14. Training Data & Metrics

数据只为判断「有没有在练」和「关系有没有变稳」。不为分析系统而加采集。

每次作答至少留下：

- 哪个关系。
- 对或错。
- 反应时间。计时从题目出现到提交答案。
- 输入方式 `input_mode`：`physical_keyboard` 或 `onscreen_keypad`。不记录设备型号。
- 发生在哪一次 session、哪一天。

每个关系至少留下当前熟练状态。每次 session 至少留下：是否做完、用了多久、正确率。

这些数据留在本机。v0.1 不上传、不建账号、不做家长报表。

反应时间是学习证据的一部分，不是单独成绩。它用于看同一个学生自己的趋势。同一种输入方式下的变化，才可以当作参考信号。跨输入方式比较时，不能直接做成熟练度结论。昨天用键盘 2 秒、今天用屏幕键盘 4 秒，不能因此说今天退步了。v0.1 不设计复杂校准算法；具体数据模型和算法留给后续 Technical Design。

# 15. Success Metrics

两类指标分开。产品指标说明学生是否还愿意练。学习指标说明练习是否真的改变了提取。只有学习指标变好、但孩子拒绝再打开，或孩子天天打开但关系毫无变化，都不能算 v0.1 成功。

**Product Metrics**

- session completion rate：开始后做到本节终点的比例。提前停止单独可见，不算失败。
- daily return：在没有人设计成打卡压力的前提下，学生是否在不同的日子自己再次开始。对第一个用户，看连续两周里实际打开的天数。
- average session length：完整 session 是否落在 5～10 分钟，而不是变成半小时题库。
- voluntary repeat usage：做完并看到结束后，学生是否在后来的日子再次开始。v0.1 不设连续打卡奖励来制造这个数字。

**Learning Metrics**

- accuracy：按关系、按域、按 session 的正确率。
- median response time：同一关系、同一学生、同一种输入方式下的反应时间中位数。用中位数，避免一次走神毁掉判断。跨输入方式不做直接比较。
- repeated-correct streak：连续答对只作为观察，不作为掌握。
- error recurrence：同一个关系再次答错的情况是否减少。
- mastery stability：进入稳定之后，在另一天是否仍然答对；动摇是否在发生后被再次练回稳定。

**什么证据说明它真的有用**

对第一个使用者，在大约两周的真实使用后同时看到：

- 学生仍然愿意自己打开，完整 session 大多落在 5～10 分钟。
- 同一批关系的正确率高于开始时。
- 在同一种输入方式下，这些关系的反应时间中位数低于开始时。若两次练习的输入方式不同，时间差不单独当作学习证据。
- 曾经错过的关系更少复发。
- 一部分关系达到稳定，并且不是全部来自同一天的连对。

v0.1 不把考试分数、班级名次或「刷题数量」当作成功标准。

# 16. Product Feedback Principles

这些是正式产品原则。

- 不制造焦虑。不使用倒计时，不因为慢而判失败，不把速度显示成学生要打败的数字。
- 正确优先于快。结束页先说对错和是否更稳，不说毫秒。
- 反应时间要记录，因为它可以辅助区分「算对」和「提取」。它是辅助证据，不是单次降级的理由，也默认不作为给学生的成绩单。跨输入方式的时间差不解释成能力变化。
- 可以在有历史时，用一句对自己的话说明「比前几天更顺」。没有历史时不说。不和别人比。
- 答对的反馈积极、短、轻。
- 答错的反馈必须能学习：看见正确关系，看见一句为什么。红叉不能是唯一反馈。
- 强调这个学生自己的变化，不强调排名、连胜压力或失败。
- 轻度完成感是允许的：做完今天、一颗星、很轻的声音和动画。它们不门控内容，不能消费，也不能用来惩罚。
- 音效可以关掉。关掉之后不损失判题、记录和结束。
- 不做羞辱用语、强烈失败动画、闪烁警告或「你太差了」这类判断。

# 17. A4 Print Mode

A4 不是装饰，也不是把一张现成数表排版后打印。

它连接两件学生本来就会做的事：屏幕上的提取，和纸笔上的提取。初中作业大量发生在纸上。如果应用里的关系和纸上写下的关系不是同一批，家庭练习会分成两个产品。打印让学生离开屏幕，仍然练那些还不稳定的关系；下一次打开应用，这些关系继续被追踪。

打印有两种来源，共用同一套题目页，不另做一套打印系统。首页「印到纸上」仍是当前不稳定关系。错题本里的打印只含当前错题。两种都是题目页，答案都不和题目同时可见。

- 纸上是题目，不是挂在墙上的答案总表。
- 答案不能和题目印在同一眼能同时看见的位置，避免打印变成查阅卡。
- 一次打印服务于当前复习，不输出三个域的完整海报。
- 打印后的纸笔结果不回传、不扫描、不识别。学生回到应用里继续作答，记录仍以应用内作答为准。
- 黑白打印应当可读。不依赖彩色才能使用。

因此，数字训练负责判题、时间和稳定性；纸笔训练负责在真实书写情境里再提取一次。两边用的是同一批关系。

产品要求是生成并预览这份 A4 题目内容。打印、分享或保存是当前客户端的能力适配，不是每个平台都必须提供系统打印机。H5 / PC 可以使用浏览器打印。小程序可以使用该平台做得到的打印、分享或保存。平台能力不足时，应明确说明，不改变学习内容本身，也不为此增加同步或后端。

# 18. Cross-device Requirements

v0.1 的发布优先级是 WeChat Mini Program First（微信小程序优先首发）。

这不等于只有微信小程序。同一学习产品可以经过这些客户端：

- 微信小程序：v0.1 首发载体。
- H5 / PC Web：一等客户端方向。
- 抖音小程序：后续适配方向。
- 支付宝小程序：后续适配方向。

不要求这四个客户端在 v0.1 同时发布。本 PRD 不选择前端框架，也不选定各端的存储 API。

同一套训练目标在手机、平板和电脑上保持一致：同样的域、同样的主循环、同样的熟练状态、同样的结束条件。

允许因设备而不同的，是输入方式，以及当前客户端如何交付 A4 预览：

- 手机和平板：屏幕数字键盘。
- PC：物理键盘，同时保留点击输入。
- A4：各端都要能生成并预览同一份题目内容。随后的打印、分享或保存，取决于该客户端做得到什么。

不允许因设备或客户端而不同的，是学习任务本身。不能出现「电脑上才能完成今天的训练」或「换一个客户端，掌握状态就变成另一套」。输入方式会改变操作时间。这个差异要被记下来，但不能被解释成数学能力本身变了。

完成一节训练不需要悬停、右键、多窗口或键盘快捷键。桌面专属操作不能成为唯一路径。

v0.1 进度只保存在当前设备、当前客户端的本地存储中，不自动跨设备同步。换设备，或清除该客户端的本地数据，进度不会跟着走。这是已知限制，不是本版要补上的同步功能。本 PRD 不选择浏览器本地存储、IndexedDB 或小程序存储 API。

# 19. Risks

| 风险 | 为什么会发生 | 产品上怎么克制 |
| --- | --- | --- |
| 机械背答案 | 关系少、问法固定，学生记住的是题目样子 | 答错时给结构提示；每个域只有少量一步应用；稳定必须跨天，不能靠当天突击；答题时不提供对照表 |
| 过度追求速度 | 反应时间一旦变成成绩，学生会抢 | 不展示倒计时和原始时间；结束页先看正确和稳定；一次慢而正确不算失败，也不把已稳定的关系降级 |
| 训练枯燥 | 重复提取本身不热闹 | 每节有终点，并控制在短时间窗；已稳定的少再出现；只保留很轻的完成感，不靠加游戏来留人 |
| 和真实数学脱节 | 孤立的口诀不会用在代数和几何里 | 少数一步应用使用同一条事实；不在 v0.1 扩展成应用题系统。迁移效果不在本版承诺 |
| 难度不匹配 | 第一个学生可能觉得 6 到 10 太容易，或 11 到 20 太难 | 集合小且可观察；已经稳定的会让出位置。要不要调整默认范围，是待验证问题，不在上线前猜成多套难度 |
| 新鲜感过后流失 | 没有班级和奖励时，几天后可能不再打开 | 成功标准里包含自愿再打开。若学生不愿再来，先视为产品假设失败，不先加排行榜或打卡惩罚 |
| 游戏化喧宾夺主 | 星星和音效变成目的 | 反馈不门控内容，没有商店和惩罚。若完成标记开始盖过对错，应删掉，而不是加更多 |
| 家长把「刷得快」理解成数学好 | 速度最容易被看见 | 学生界面不突出速度。产品对 Owner 的解释以稳定和正确为准。v0.1 仍不做家长后台 |
| 训练数据误导 | 一天连对、中途放弃、换设备丢失，或把手机点按和键盘输入放在一起比时间，都会让「进步」失真 | 掌握必须跨天；未完成 session 单独标记；一次慢不降级；反应时间只在同一输入方式内用中位数作参考；进度只解释为本机记录 |

# 20. Open Questions

下面这些问题本轮不拍板。它们不阻止 PRD 进入评审，但在冻住对应行为之前需要 Owner、后续 UX、真实使用或技术设计之一来决定。

1. 一节训练的终点，用大约 5 分钟还是更接近 10 分钟更合适？完整做完时应当出多少题？
2. 第一次使用要不要做诊断？当前建议是不做考试式诊断，从少量入口关系开始。这个建议尚未确认。
3. 同一节里，错过的关系隔开几题再出现，最多再出现几次？
4. 正确但很慢时，「慢」相对这个学生自己的哪一次表现来判断？
5. 若将来做小数 → 分数，是否必须最简分数？在这条决定之前，该方向不进入 v0.1。
6. 默认平方范围（6² 到 20²，外加 25²），在第一个学生身上是太宽、太窄，还是合适？
7. 少量一步应用是否进入第一批可练习内容，还是等直接提取被证明愿意被使用之后再加？
8. 结束页那句「比前几天更顺」是否在第一版就给学生看？原则是不展示原始时间；这句定性反馈还可以拿掉。
9. 本机进度丢失时，除了一句说明，是否需要学生可自行保存的导出？导出不是账号同步。当前建议是 v0.1 不做。

已经在本 PRD 里作为产品建议定下、因而不再开放的包括：不做倒计时；不把原始反应时间给学生当成绩；答对一次不算掌握；一次正确但慢不单独把稳定降为动摇；反应时间不跨输入方式直接解释成能力变化；常用乘积和分数 → 小数都是候选范围内不超过 40 个的精选，不是全集；v0.1 只有三个域；不登录也能完成核心验证；分数方向只做分数 → 小数。具体题目清单、多慢算慢、连续几次算异常、是否按设备做校准，都不在本轮决定。

# 21. v0.1 Acceptance Criteria

Owner 和后续 UX、UI、技术角色可以用下面这些标准判断首版是否达到产品意图。它们不是代码测试。

1. 学生不登录，就能在手机上做完一次今日训练：出题、输入、判题、反馈、结束。
2. 学生可以只选平方、常用乘积或分数到小数中的一个域，完成一次专项，规则与今日训练一致。
3. 学生在 PC 上用键盘也能完成同一次训练；只靠点击同样能完成。
4. 平板上的训练任务与手机相同，不出现另一套模式。
5. 答错后，学生能看到正确关系，以及一句和这条关系有关的提示，而不只是错误标记。
6. 答题过程中看不到供对照的完整数表，也看不到倒计时。
7. 系统能在本机留下每次作答的对错、反应时间，以及输入方式是物理键盘还是屏幕数字键盘。不要求留下设备型号。
8. 错过的关系会在后续训练中再次出现，而不是错过一次就从队列消失。
9. 只答对一次的关系不会被呈现为已经稳定。一次正确但慢，也不会把已经稳定的关系呈现为动摇。
10. 学生结束时能看到这次的正确率，以及和自己有关的稳定情况；看不到别的学生，也看不到原始反应时间。
11. 学生提前离开时，已经完成的作答还在。
12. 学生能查看最近几次是否练习、正确率，以及哪些关系还不稳定。
13. 学生能生成并预览当前不稳定关系的 A4 题目页，且题目和答案不会排成一张对照表。当前客户端能打印、分享或保存时可以继续；不能时会说明。
14. 关闭音效后，训练、判题和记录仍然完整。
15. 三个域都是精选后的有限集合，每个域不超过 40 个关系。常用乘积不是 6 到 19 的全部组合。分数 → 小数不是候选分母下的全部组合。
16. 首版在没有后端、没有账号的情况下，能够完成上面的核心流程。
17. 首版不包含第 10 节列出的登录、班级、排行榜、支付、AI、OCR、手写和其他训练域。

# 22. Future Directions

只有在 v0.1 的使用证据支持「学生愿意再练，且关系变得更稳」之后，才考虑扩展。顺序不做承诺。

- 在同一三个域内补充问法，例如开方，或小数 → 分数。后者取决于最简形式是否已经决定。
- 增加新的训练方向，例如立方、整数次方、相邻整数的和与积、补数、半值与倍值。每一项都要按同样方式做成小的关系集合，而不是搬入一套现成表。
- 把同一训练模型延伸到小学高年级、高中基础计算或成人脑力训练。那是新的用户和内容决定，不是 v0.1 的设置开关。
- 在确实需要换设备或给家长看进度时，再单独讨论账号和同步。不提前做。
- 客户端方向已经分开，不把下面三项写成同时发布的路线图。微信小程序是 v0.1 首发载体。H5 / PC Web 是一等客户端方向。抖音小程序和支付宝小程序是后续、同一核心上的适配方向。v0.1 不承诺四个平台一起发布。交互模型不绑死在某一个平台的专有操作上。

扩展时仍然保持本 PRD 的边界：有限关系、提取而不是题海、正确优先于速度、Owner 对产品价值的判断先于功能增加。
